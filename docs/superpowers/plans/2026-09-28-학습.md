## 스펙에서 바꾸는 것 — torch 대신 넘파이

스펙 §5.1 은 torch 를 적었다. 이 환경에서 `download.pytorch.org` 는 막혀 있고(확인함), PyPI 의 리눅스 torch 는 CUDA 의존까지 수 GB 라 세션마다 받는다
(스펙 §11 이 이미 짚은 위험이다). 망은 모수 1,900 개의 MLP 라 torch 가 주는 것이 없다 — 순전파 · 역전파 · Adam 을 넘파이로 직접 쓴다(백 줄 남짓).
기울기는 유한 차분으로 검사한다(`test_net.py`). 따라서:

- `requirements.txt` = numpy · pandas(버전 고정). 세션 훅이 `ml/.venv` 에 깐다 — 실패해도 세션은 선다(`check` 는 넘파이가 필요 없다).
- 스펙 §5.7 의 "torch(float32)와 골든(float64)이 1e-4 안" 은 "넘파이(float64 · 행렬곱)와 골든(float64 · 입력 순서의 덧셈)이 1e-9 안" 이 된다 —
  행렬을 뒤집어 쓴 것 같은 실수를 잡는 목적은 같고, 남는 차이는 BLAS 의 덧셈 순서뿐이다.
- 결정론: 시드 고정(`numpy.random.default_rng`) · BLAS 한 스레드(`OPENBLAS_NUM_THREADS=1` 등) — 같은 기기에서 같은 가중치.

## Global Constraints

- 나누기는 **봇 번호**로 — 학습 0 ~ 79,999 · 검증 80,000 ~ 89,999 · 시험 90,000 ~ 99,999. 같은 봇의 사례가 양쪽에 새면 외운 것을 일반화로 착각한다.
- 표준화는 학습 몫의 평균 · 편차(모집단 편차). 편차가 0 인 열은 1.
- 기저율 = 학습 몫의 칸마다 맞은 몫. `network.json` 의 `baseline` 은 그 **로짓** — 로그는 파이썬에서만 한 번(스펙 §8).
- `heads` = `stages.json` 2단계의 `patterns` 순서 · `features` = `samples.csv` 머리의 입력 이름(= `PlayerFeatures.Names`).
- 수는 파이썬 `repr` — 가장 짧은 왕복 표기라 C# `double.Parse` 가 같은 double 을 얻는다.
- `trained_on.commit` 은 원본을 지은 커밋(매니페스트) · `data_digest` 는 매니페스트의 값이고, 지금의 `overfit/data` 로 다시 셈해 다르면 멈춘다.
- 골든의 연산 순서(스펙 §5.7): `z = (x - mean) / std` → 층마다 출력 j 에 `acc = b[j]` 에서 입력 순서대로 `acc += w[j][i] * z[i]` → 마지막 층을 빼고
  ReLU = `acc if acc > 0 else 0.0`(−0 · NaN 이 C# 의 `Math.Max` 와 갈리지 않게).

## Review Focus

1. **칸을 가린 손실** — 사례 하나는 제 칸의 머리만 가르친다. 다른 머리의 기울기가 0 인지 테스트가 본다.
2. **관문의 겨냥** — 습관형 봇(시험 몫)의 시도마다 그 패턴의 들어 올림(로짓 − 기저율의 로짓)을 내 평균한다. `lift_min` = ln 1.5(스펙 §6.4 — 4번 PR 이
   `balance.json` 으로 옮긴다).
3. **골든이 C# 과 같은 순서인가** — 덧셈 순서 · ReLU 의 모양. C# 쪽은 4번 PR 의 `PlayerNet` 이 `==` 로 본다.
