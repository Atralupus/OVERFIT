# 조각 4 — 학습 환경 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 판을 강화학습의 경험(관측 · 마스크 · 칸 · 확률 · 가치 · 보상)으로 바꾸는 일꾼과 그것을 읽는 파이썬.

**Architecture:** 순수 규칙 층에 관측(`BossObservation`) · 정책망(`PolicyNet`) · 망 조종기(`NetController`). 공장 콘솔에 `--rollout` 모드(`RolloutRun` · `RolloutWriter`)를 더하고 `tools/build.sh rollout`. 파이썬은 `ml/rl/rollout.py` 가 넘파이로 읽는다.

**Spec:** `docs/superpowers/specs/2026-10-01-조각4-학습-환경-design.md`

## Global Constraints
- 규칙 조종기의 판은 그대로(골든 · 공장 지문). 관측은 원하는 조종기에게만 짓는다.
- 새 순수 파일은 두 csproj 에 링크 · `.uid`. 공장 쪽 파일(`tools/factory/*.cs`)은 테스트 csproj 에 링크한다(공장의 순수 절반 규약).
- 파이썬은 `ml/.venv`(numpy) — `tools/build.sh` 가 경로를 안다.
- `[E]` 는 실패. `tools/build.sh check` 초록.

## Review Focus
- 관측 칸의 자리가 표와 어긋남(원핫의 칸 수 · 순서) — 망이 다른 칸을 읽는다.
- 보상이 강제 결정(자유로워짐)을 건너며 새거나 두 번 붙음 — 판의 체력 변화와 합이 안 맞는다.
- 스레드 수에 따라 출력이 달라짐.
- 가중치 JSON 의 칸 수 · 명부가 판과 다를 때 조용히 돔.
- 판이 끝나는 틱의 마지막 결정의 done 과 끝 보상.

### Task 1: 관측
- 테스트 `BossObservationTests`: Size · 칸 자리 · 정규화 · 18틱 앞 · 최근 K · 나는 폭탄 · 규칙 조종기 판은 관측을 안 짓는다.
- 구현: `FighterSnapshot` 확장(스태미나 비 · 던지기 진행) · `SightBuffer` 길이 · `At(back)` · `BossObservation`(입력 레코드 + `Encode`) · `IBossController.WantsObservation` · `BossDecision.Observation`.

### Task 2: 정책망 · 망 조종기
- 테스트 `PolicyNetTests` · `NetControllerTests`.
- 구현: `PolicyNet`(JSON · 순전파 · 거절) · `NetController`(소프트맥스 · `Det.Roll01` · 기록).

### Task 3: 일꾼
- 테스트 `RolloutRunTests`: 보상 합 · 스레드 무관 · `[E]` 없음.
- 구현: `tools/factory/RolloutRun.cs` · `RolloutWriter.cs` · `RolloutProgram.cs` · `Program` 의 `--rollout` · `ml/rl/train.json` · `tools/build.sh rollout`.

### Task 4: 파이썬 · 처리량 · PR
- `ml/requirements.txt` · `ml/rl/rollout.py` · `ml/rl/test_rollout.py` · `tools/build.sh` 의 `ML_PYTHON`. 처리량 두 줄을 PR 에.
