# 조각 2 — 폭탄 · 끊으려는 보스 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 파이터가 한 판에 10개의 폭탄을 던지고(1.5초 선딜 · 보스를 따라가 떨어짐 · 피해 60), 보스는 던지기를 보면 어떤 동작 중이든 반응 지연 뒤 가장
가까운 끊을 자리에서 끊고 멈칫 → 돌진으로 던지기를 끊으려 한다.

**Architecture:**
- 규칙 층(순수 · 테스트가 링크한다): 파이터에 행동 `Throw` 를 더한다(틱으로 센다 · 놓기 전에 맞으면 잃는다). 나는 폭탄은 새 파일 `Bombs` 가, 보스가 던지기를
  보고 · 알고 · 끊을 자리를 묻는 일은 새 파일 `BombWatch` 가 든다. `BattleSim` 은 주석 빼고 427줄이라 둘을 부르기만 하고, 계획의 달리기를 `PlanRun` 으로
  떼어 내 자리를 만든다(CLAUDE.md §7). 입력은 `InputFrame.Bomb` · 코드 0 ~ 191 로 넓힌다.
- Godot 쪽: `Battle` 이 L 을 읽고, 뷰가 던지기 · 나는 폭탄 · 터짐 · 알아챔 표시 · HUD 의 개수를 그린다. 데모 봇이 던진다.
- 기록: 시도 한 줄에 `bombs`, 되살리기가 견주고, 결과 화면에 한 줄.

**Tech Stack:** C# 12 (.NET 8) · xunit v3 + Shouldly · Godot 4.7.2 mono · bash

**Spec:** `docs/superpowers/specs/2026-09-30-조각2-폭탄과-반응-design.md`. 우산 `2026-09-29-똑똑한-보스-design.md` §8 의 조각 2(이 조각이 §1 · §3.3 · §4 · §5 ·
§8 · §10 을 고쳤다 — 스펙 §7).

## Global Constraints

- **수치는 JSON 에**(CLAUDE.md §3) — `fighters.json` 의 `bomb`: `count` 10 · `throw_seconds` 1.5 · `recover_seconds` 0.25 · `flight_seconds` 0.5 ·
  `damage` 60 · `anim` `attack` · `windup_frame` 1 · `release_frame` 4. `bosses.json` 의 `bomb_reaction`: `delay_seconds` 0.3 · `hesitate_seconds` 0.25 ·
  `move` `돌진`. 그림 수치는 `balance.json` 의 `feel`.
- **틱**: 던지기 = 누른 틱부터 90틱 선딜(90번째 틱 끝에 놓는다) → 15틱 경직. 폭탄 30틱. 반응 지연 18틱 · 멈칫 15틱. 끊으려면 판정이 **누른 틱 + 88 까지** 닿아야
  한다(같은 틱은 파이터 → 보스 순서라 놓는 틱의 판정은 늦다).
- **`Det.Domain` 은 더하기만** — 16 `bot_bomb`(데모 봇이 던지나). 보스의 반응은 난수를 안 쓴다.
- **입력 코드는 계약이다** — 폭탄 누름은 96 위에 얹는다(0 ~ 191). 0 ~ 95 의 뜻은 안 바뀐다.
- `[E]` 는 규칙 위반만이다. 폭탄 · 반응은 `[E]` 를 새로 안 낸다(없는 반응 동작은 판을 세울 때 `ArgumentException`).
- **TDD 게이트:** 링크된 규칙 파일을 고치는 커밋은 `tests/` 변경을 같이 싣는다. **스테이징과 커밋을 한 명령에 붙이지 않는다**(훅이 add 이전을 본다).
- 새 `overfit/*.cs` 는 `.uid` 가 짝이다(`GODOT_PATH=/usr/local/bin/godot tools/build.sh import`). 새 순수 파일은 테스트 csproj 에 한 줄(공장이 쓰면 공장 csproj 에도).
- **리플레이 골든**(`tools/replay_golden.txt`)이 움직이면 파일에 날짜 · 무엇이 · 왜를 적고 PR 설명에도 적는다.
- PR 은 main 에서 지정 브랜치(`claude/laughing-maxwell-1eps2e`)를 새로 따서(머지된 뒤 `git checkout -B … origin/main`) 올리고, 설명에
  `#141 의 k/5` 를 적고(마지막은 `Closes #141`), check 가 초록이면 squash 로 직접 머지한다.
- 주석은 왜를 적는다 · 바꾼 코드 위의 낡은 주석은 같이 고친다(CLAUDE.md §9). README 한국어는 합니다체.

## Review Focus

1. **놓는 틱의 순서** — 누른 틱 + 88 에 닿은 판정은 던지기를 끊고, + 89(놓는 틱)에 닿은 판정은 못 끊는다(2/5 · `FighterThrowTests` · `BombTests`).
2. **반응과 계획한 캔슬이 같은 틱** — 반응이 이기고 계획의 잇는 동작은 안 선다(3/5 · `BombReactionTests`).
3. **버린 계획의 캔슬이 반응의 돌진을 끊지 않는다** — 반응이 계획을 끝내면 `PlanFlow` 의 남은 캔슬도 지운다. 안 지우면 돌진이 옛 계획의 지점 틱에 끊긴다
   (3/5 · `BombReactionTests`).
4. **멈칫 · 반응 중의 탈진** — 반응이 끝나고 탈진이 풀린 뒤 다음 계획의 쉬기부터다(3/5).
5. **옛 기록 줄** — 코드 0 ~ 95 · `bombs` 없는 줄이 그대로 읽히고 되살아난다(2/5 · 4/5 · `InputTapeTests` · `AttemptLogTests` · `ReplayTests`).
