> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 성향을 받는 봇(`FleetBot`)을 세우고 계측에 11번째 축 `guard_rate` 를 더한다 — 성향을 올리면 짝지은 축이 움직이는지가 관문이다.

**Architecture:**
- 규칙 층(`overfit/battle/rules/**` · 순수 C# · 테스트가 링크)에 새 파일 넷: `BotTraits`(성향 · 뽑기) · `FleetConfig`(`fleet.json` 의 DTO) · `BeatTable`(리듬형이 따르는 시각표) · `FleetBot`(봇). 잡음은 `BotTraits` 옆의 작은 정적 함수(`BotNoise`)다.

- `PlayerAxes` 에 `GuardRate`. 10축을 말하던 주석 · 테스트 · README · 데모 줄을 11축으로 고친다.
- `Det` 에 도메인 7 `fleet_bot` · 8 `fleet_act` · 9 `fleet_timing`.

**Tech Stack:** C# 12 (.NET 8) · xunit v3 + Shouldly

**Spec:** `docs/superpowers/specs/2026-09-28-패턴-고르는-망-design.md` — §2(자리) · §3(봇 함대 전부) · §8(도메인 표의 7 ~ 9) · §9 의 1번 줄 · §10 의 1번 줄.

## Review Focus

1. **돌진 중의 `NextActiveIn` 은 추정이다** — 도착까지 시계가 서서 값이 틱마다 바뀐다. 봇은 계획(수단 · 오차)을 판정마다 한 번만 뽑고 누를 틱만 매 틱 다시 셈해야 한다 — Task 5 가 `1타 돌진` 을 대본으로 한 판 돌려 예외 · NaN 없이 끝나는지 본다.
2. **굳은 파이터(탈진 · 붙들림)** — 누름이 안 먹는 틱에 "눌렀다" 로 적으면 그 판정의 회피를 통째로 건너뛴다. 실제로 행동이 선 틱에만 눌렀다고 적는다 — Task 5 의 테스트.
3. **리듬형인데 시각표가 모자라다** — `점프 3연속` 은 셋째 착지까지 있는데 기준(`점프 공격`)은 하나다. 모자란 칸은 눈으로 잰다 — Task 4 와 Task 5.
4. **바깥으로 대시** — 대시는 바라보는 쪽으로만 간다. 바깥이면 한 틱 돌아서고 다음 틱에 누른다 — Task 5 가 `DashDirectionBias` 가 음수로 나오는 봇을 본다(Task 6 의 관문과 같은 것을 작게).
5. **가드 비중이 1 에 가까운 봇** — 판정마다의 수단 비중(대시 · 점프 · 패리)이 0 에 가까워도 나눗셈이 0 으로 안 떨어져야 한다 — Task 3 의 뽑기 테스트(비중의 합 1 · 각 칸 > 0).

### Task 5: `FleetBot`

**Files:**
- Create: `overfit/battle/rules/FleetBot.cs` · 링크 한 줄
- Test: `tests/Overfit.Rules.Tests/Battle/FleetBotTests.cs`

**Interfaces:**
- Consumes: `BotTraits` · `BotNoise` · `BeatTable` · `Det.Domain.FleetAct`
- Produces: `public sealed class FleetBot` — `FleetBot(BotTraits traits, ulong seed, BeatTable beats, FighterConfig fighter)` · `public InputFrame Next(BattleSim sim)`. `seed` 는 시도 시드다(`BotPolicy` 처럼 판과 같은 시드).

규칙(스펙 §3.1 · §3.3) — 테스트가 다 정하지 않는 알고리즘이라 여기 적는다:
- **패턴 사례** — `Boss.CurrentPattern` 이 null → id 로 바뀌는 틱: 사례 번호를 올리고, 선 틱 · 판정 번호(0) · 계획(null)을 새로 두고, **이번 패턴을 가드로 받을지** 한 번 굴린다 — `Roll01(seed, FleetAct, k1: 사례, k2: 0) < Guard`.
- **선딜의 시작** — `BossStep?.Kind` 가 `"windup"` 이 아니다가 `"windup"` 이 되는 틱(사례가 선 틱 포함). 반응 지연은 여기서 잰다.
- **판정 번호** — `SwingLive` 가 참에서 거짓이 되는 틱에 하나 오르고 계획을 지운다.
- **지키기** (패턴이 돌고 · 보스가 안 탈진했고 · `SwingLive` 거나 `NextActiveIn` 이 있을 때): 가드 사례면 `GuardHeld` 를 붙든다. 아니면 판정마다 계획을 **한 번** 뽑는다 — 키 = 계획 번호 · `k2`: 1 욕심 · 2 수단 · 3 리듬 · 4 대시 방향.
  - 욕심(`< Greed`)이면 이 판정을 안 피하고 사거리 안이면 칼을 누른다.
  - 수단은 대시 · 점프 · 패리를 비중대로(합으로 나눠) 고른다.
  - 리듬(`< Rhythm` 이고 `BeatTable.For(패턴)` 에 이 판정 번호의 칸이 있으면): 기대 판정 틱 = 사례가 선 틱 + 시각표[번호] / Dt. 아니면 눈: 지금 틱 + (`SwingLive` 면 0 아니면 `NextActiveIn`) / Dt — **매 틱 다시 셈한다**(Review Focus 1).
