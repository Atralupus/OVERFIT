# 검증 — 패턴을 고르는 망 5번 PR 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 같은 봇에게 망 보스와 무작위 보스를 붙여 §7.1 의 다섯 줄을 잰다. 사람의 기록이 쌓이면 sim-to-real 을 잴 도구를 세운다. 수치와 판정을 README 에
싣는다. 선을 못 넘으면 문턱을 조용히 고치지 않는다 — 멈추고 까닭을 적는다.

**Architecture:**
- 규칙 층(순수 · 테스트가 링크한다)
  - `StageRoster.Setup` 에 갈래를 정해 넘기는 칸 — 평가가 게임과 같은 자리에서 두 갈래를 세운다.
  - `InstanceTracker` 를 공장에서 규칙 층으로 옮긴다 — 사례의 라벨을 공장과 게임이 같은 코드로 짓는다.
  - `AttemptEntry` 가 사례(패턴 · 맞았나)와 시도를 시작할 때의 입력 19칸을 싣는다(없는 옛 줄도 읽힌다).
- Godot 쪽: `Battle` 이 틱마다 사례를 가르고 끝날 때 기록에 싣는다.
- 공장(`tools/factory`): 평가 모드(`--evaluate`) — 봇마다 1단계 한 번, 2단계를 망 갈래 · 무작위 갈래로 한 번씩(같은 시도 시드). `FactoryBatch` 를 결과
  타입에 매이지 않게 한다.
- 파이썬(`ml/`): `validate.py`(§7.1 · 부트스트랩 · `ml/validation.md`) · `sim2real.py`(분포 밖 · 보정 · 갈래 비교).

**Tech Stack:** C# 12 (.NET 8) · xunit v3 + Shouldly · Godot 4.7.2 · numpy · pandas · bash

**Spec:** `docs/superpowers/specs/2026-09-28-패턴-고르는-망-design.md` — §7 전부 · §9 의 5번 줄 · §10 의 5번 줄.

## Global Constraints

- 문턱(`lift_min` · `max_targeted`)과 규칙은 이 PR 에서 안 고친다 — 선을 못 넘으면 까닭을 적고 멈춘다(§7.1). #113 의 이른 측정은 「약점 저격이
  아니다」가 못 미칠 것으로 봤다(고르게 약한 봇의 다섯 전부 38.9%).
- 평가의 봇은 학습에 안 쓴 봇이다 — 함대 시드 1 · 봇 100,000 부터(원본은 0 ~ 99,999).
- 두 갈래는 같은 1단계 기록 · 같은 시도 번호 · 같은 시도 시드에서 갈라진다. 판은 `StageRoster.Setup` 이 세운다 — 평가만의 길을 두지 않는다.
- 평가 파일은 스레드 수와 무관하게 바이트까지 같다(공장과 같은 약속 · §4.5).
- 라벨 · 입력은 C# 이 한 번 짓는다 — 파이썬이 따로 지으면 두 벌이 갈린다(`PlayerFeatures` 와 같은 까닭).
- 리플레이 골든은 안 움직인다 — 링크된 규칙 파일을 바꾼 커밋마다 "안 움직였다" 블록.

## Review Focus

1. **두 갈래가 정말 같은 자리에서 갈라지나** — 1단계 기록 · 시도 번호 · 시드가 같고, 무작위 갈래의 첫 2단계 시도가 공장(`BotRun`)의 그 시도와 같은
   사례를 낸다(테스트).
2. **사례의 라벨이 옮긴 뒤에도 같다** — `InstanceTracker` 의 테스트는 그대로 돈다 · 원본의 sha256 이 옮기기 전과 같다.
3. **옛 기록 줄이 읽힌다** — `instances` · `features` 가 없는 #113 의 줄.
4. **지표의 정의** — 짝지은 부트스트랩(봇을 다시 뽑는다) · 의존 봉인의 (가) 몫의 비 · (나) 맞는 비율의 차 · 숨통 · 다섯 전부의 몫 · 승률의 비 · ECE.
