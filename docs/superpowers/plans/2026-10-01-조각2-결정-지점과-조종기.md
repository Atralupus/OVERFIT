**Goal:** 보스의 판단을 결정 지점마다 한 목록에서 고르는 조종기(`IBossController`)로 옮기고, 규칙 조종기가 0.11 과 한 틱도 다르지 않은 판을 내게 한다.

## Review Focus

- **폭탄 반응과 결정이 같은 틱** — 반응이 이긴다(0.11 그대로 · `ReactNow` 를 결정보다 먼저 본다). 반응의 동작 중에는 캔슬 지점에서 안 묻는다.
- **다가가는 중 탈진 · 전환** — 달리기가 끊기고 다음 결정은 자유로워짐이다. 달리기 상태가 남으면 다음 다가가기가 옛 상한을 이어 센다.
- **틀린 계획(plan_invalid) 뒤의 다시 고르기** — 가장 짧은 쉬기 뒤 번호 + 1 로, 그 틱부터 새 쉬기.
- **무작위 조종기가 가려진 칸을 못 내는가** — 마스크 밖이면 `[E]` 이고 판이 기다리기/계속하기로 간다.
- **늦은 관측의 고리** — 판 초반(18틱 전)에는 첫 모습 · 고리가 틱마다 한 칸씩 민다(히트스톱은 판이 틱을 안 밀어 상관없다).

`RuleController` 는 `PlanFlow` 의 `Choose` · `Problem` · `Entry` 를 그대로 옮기고(주석도), 흐름만 결정의 칸으로 바꾼다:

| `Point` | 하는 일 |
|---|---|
| `Freed` | `Choose()`(번호 + 1 · 틀리면 `_plan = null` · `[E] plan_invalid`) · `_base = d.Elapsed` · 기다리기 |
| `Rest` | 계획 없음: `d.Elapsed − _base ≥ 가장 짧은 쉬기` 면 `Choose()` · `_base = d.Elapsed` · 기다리기. 계획 있음: `d.Elapsed − _base ≥ plan.RestTicks` 면 달리기면 다가가기 · 아니면 첫 동작(`_cancelPending = plan.CancelPoint is not null`) · 아니면 기다리기 |
| `Approach` | 다가가기 |
| `Arrived` | 첫 동작(`_cancelPending` 같이) |
| `Cancel` | `_cancelPending && d.CancelPoint == plan.CancelPoint` 면 `_cancelPending = false` · 잇는 동작 · 아니면 계속하기 |

`PlanRequest` 는 `d.Sight` 로 짓는다: `new PlanRequest(number, d.Sight.Tick, d.Sight.Events, d.Sight.BossX, d.Sight.BossFacing, d.Sight.Fighter.X, d.Sight.Form)`.

판의 바뀌는 자리(옛 `_flow` 호출 열 곳):

| 옛 | 새 |
|---|---|
| 생성자 `_flow.Choose()` | `Freed()` — `Decide(Freed)` · `_sinceDecision = 0` · `_elapsed = 0` |
| `EndPattern` · `Exhaust` · 전환 끝의 `_flow.Choose()` | `Freed()` |
| `React` · `BeginShift` 의 `_flow.Drop()` | 지운다(달리기는 `ClearPattern` 이 걷는다). 규칙 조종기는 다음 `Freed` 에 새 계획을 고른다 |
| 쉬는 틱의 `_flow.RestTick()` | `_elapsed++` · `_sinceDecision++` · 12 면 `Decide(Rest)` 후 실행 |
| 달리기 중 `RunStep()` | 걸음 뒤 닿음/상한이면 `Decide(Arrived)` · 아니면 `_sinceDecision++` 이 12 면 `Decide(Approach)` |
| 캔슬 지점의 `_flow.CancelAt` | 러너가 지금 동작의 캔슬 지점 틱에 들 때(`_watch.InReaction` 이 아니면) `Decide(Cancel)` |
| `Plans` · `PlanEntries` | `Controller is RuleController r ? r.Plans : []` |

실행:

```csharp
    private void Act(int action, DecisionPoint at)
    {
        _sinceDecision = 0;
        if (action == BossActions.Approach)
        {
            if (!_run.Active)
            {
                StartRunStep();   // 옛 StartRun 에서 move 를 뺀 것 — 시작하고 같은 틱에 한 걸음
            }
            return;               // 이어서 고르면 같은 달리기가 이어진다
        }

        _run.Clear();
        if (_actions.RosterIndex(action) is int i)
        {
            Begin(i);
        }
        // Wait: 제자리 · Continue: 러너를 그대로 민다
    }
```

`PlanRun` 은 `move` 를 안 든다 — `Start(Boss, fighterX, bounds, tick)` · `Step(...)` 은 닿았거나 상한이면 참(`bool`)을 돌린다(로그 그대로).

마스크(`bool[]` 길이 `_actions.Count`):
- `Freed`: 기다리기만.
- `Rest` · `Approach` · `Arrived`: 기다리기 · 다가가기 · 동작 전부.
- `Cancel`: 계속하기 · 지금 동작이 아닌 동작 전부.

가려진 칸이 오면 `[boss][E] action_masked act=<이름> at=<지점> tick=…` 를 한 번 남기고 `Freed`/`Rest`/`Approach`/`Arrived` 는 기다리기, `Cancel` 은 계속하기로 간다.

관측: `Tick` 의 `Fighter.Tick` 뒤에 `_sight.Push(Snapshot())`. `Decide` 가 `new BossSight(Ticks, _forms.Form, Boss.X, Boss.Facing, Boss.Health, _sight.Delayed, Events)` 를 싣는다.

로그: 결정마다 `[boss][D] decide at=… act=… open=… tick=…` (레벨을 먼저 묻는다 — `Strike` 의 할당 주석).
