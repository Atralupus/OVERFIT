# 조각 1 — 페이즈

**상태:** 설계 (2026-10-01) · 이슈 #150 · 우산 #149
**잇는 설계:** `2026-10-01-강화학습-보스-design.md`(우산) §2 · §9 의 조각 1. 우산 §11 에서 조각 1 이 정할 것(전환의 길이 · 플래시 횟수 · 무적 동안 날아오는
폭탄)을 여기서 정한다. 어긋나면 우산이 이긴다.

수치는 코드가 아니라 JSON 에 둔다.

---

## 0. 유저가 말한 것 · 정한 것

> "각 분기는 보스 체력을 1200으로 늘리고 1페이즈는 피 900남았을때 2페이즈 전환, 3페이즈는 피 400 남았을때 전환입니다. 각 페이즈 전환에는 무적상태가 되고
> idle애니메이션에서 흰색으로 몇번 플래시됐다가 무적 풀리면서 페이즈 전환정도로 하면 됩니다." (2026-10-01)

| 물음 | 정한 것 |
|---|---|
| 체력 · 문턱 | 1200 · 남은 체력 900 · 400 (`bosses.json`) |
| 전환의 길이 | **1.5초(90틱)** — 탈진과 같은 길이. 흰 플래시 셋이 읽히는 가장 짧은 길이 |
| 플래시 | **세 번** — 뷰만 읽는 수치(`balance.json` 의 `feel`) |
| 문턱을 넘는 피해 | **문턱에서 멈춘다**(우산 §1 가정) — 페이즈마다 깎을 체력이 300 · 500 · 400 |
| 무적 동안의 칼 · 폭탄 | 피해 · 경직 채움 · 맞은 플래시 없음. 떨어진 폭탄의 기록은 `landed` 그대로이고 로그가 막혔다고 말한다(§2.3) |
| 전환 중 보스 | idle 로 제자리에 서고 돌아서지 않는다(탈진과 같다) · 공중이면 높이만 따라 내린다 |
| 세 페이즈의 조종기 | 셋 다 지금의 보스(무작위 계획 + 폭탄 끊기). 고르기에 페이즈 번호만 넘긴다 — 조각 7 의 자리 |

## 1. 데이터

```jsonc
// bosses.json 의 "그림"
"max_health": 1200,
"forms": { "thresholds": [900, 400], "shift_seconds": 1.5 }
```

**코드 · 데이터의 이름은 `form` 이다** — `BossPhase`(선딜 · 판정 · 후딜)가 이미 있어 "phase" 를 쓰면 겹친다. 유저에게 보이는 말(결과 화면 · README)은 "페이즈" 다.

- `thresholds` 는 **내려가는 순서**이고 모두 0 보다 크고 `max_health` 보다 작다. 페이즈 수는 `thresholds` 길이 + 1 이다. 어기면 판을 세울 때 거절한다(`BattleSim` 이 빈 명부를 거절하는 것과 같다) — `BossDataTests` 가 데이터를 먼저 본다.
- `forms` 는 필수 키다(`required`) — 빠지면 부팅이 빠진 키를 나열하고 멈춘다(CLAUDE.md §3).
- 뷰: `balance.json` 의 `feel.boss_form_flashes: 3`.

## 2. 규칙

### 2.1 바닥

보스는 **바닥**을 안다 — 지금 페이즈의 다음 문턱(마지막 페이즈면 0). 피해는 바닥 아래로 안 깎는다(`Boss.TakeDamage`). 칼과 폭탄 둘 다 이 한 곳을 지난다.

### 2.2 전환

판의 틱 순서(보스 판정 → 칼 → 끊기 → 폭탄 → 승패)에서 **폭탄 뒤 · 승패 앞**에 본다: 체력이 바닥(> 0)에 닿았고 전환 중이 아니면 그 틱에 전환을 시작한다.

1. 하던 동작 · 달리기 · 멈칫을 걷는다(탈진과 같은 걷기 — 열린 창은 관측 없이 버린다 · `_swings.Cut(Ticks, "form")`). 공중이면 높이만 따라 내린다.
2. 경직 게이지를 비우고, 탈진 중이면 탈진을 끝낸다(같은 틱에 게이지로 무너졌어도 전환이 이긴다).
3. **무적**이 된다. 전환 시계 90틱.
4. 계획을 고른다(`_flow.Choose`) — 쉬기는 전환이 끝난 뒤부터 센다(탈진과 같다).
5. 전환이 끝나는 틱에 페이즈 번호가 오르고 바닥이 다음 문턱이 되며 무적이 풀린다.

전환 중 보스는 아무것도 안 한다 — 돌아서지도 않는다. 파이터는 그대로 움직이고 던진다.

### 2.3 무적

- 칼: 닿아도 피해 · 경직 채움이 없다. 그 칼질은 닿은 것으로 친다(한 칼질에 한 번).
- 폭탄: 떨어져도 피해가 없다. 기록의 결과는 `landed` 이고, 로그는 `dmg=0 shielded=1` 이다. `BombOutcome` 은 늘리지 않는다 — 기록 모양이 바뀌면 되살리기가 깨진다.
- 보스의 반응(`BombWatch`)은 전환이 걷는다. 전환 중에 본 던지기는 전환 뒤에도 끊을 자리를 기다린다(본 틱은 그대로).

### 2.4 고르기에 넘기는 것

`PlanRequest` 에 `Form`(1 부터)를 더한다. 조각 1 의 고르기는 읽지 않는다.

### 2.5 시작 체력 — 대본 전용

GIF · 스크린샷이 전환을 찍으려면 300 을 깎아야 한다. `BattleSetup.BossStartHealth`(없으면 최대 체력)를 두고 **대본으로 선 판만** 쓴다. 시작 페이즈는 시작 체력이
든 칸이다. 문턱과 같으면 `[E]`. 대본이 시작 체력을 쓰면 시도 기록에 `boss_start_health` 를 싣고 되살리기가 그대로 세운다.

### 2.6 로그

| 줄 | 레벨 |
|---|---|
| `[boss][I] form_shift from=1 to=2 hp=900 tick=…` | 전환 시작 — 유저가 보는 사건 |
| `[boss][I] form=2 tick=…` | 전환 끝 |
| `[boss][D] shielded src=strike\|bomb dmg=… tick=…` | 무적이 막은 피해 |

## 3. 기록 · 되살리기 · 결과

- 시도 기록 한 줄에 `form_shifts`: 전환을 **시작한** 틱들(없으면 빈 배열).
- 되살리기가 `form_shifts` 를 견준다(0.11 이하의 줄은 없으므로 안 견준다 — 체력이 달라 어차피 `replay_data_changed` 다).
- 결과 화면: 페이즈마다 걸린 시간 한 줄 — 예) `페이즈 1 0:42 · 2 1:10 · 3 —`(못 간 페이즈는 —).

---

## 4. 뷰

- **보스:** 전환 동안 idle 을 돌고, 흰 플래시가 `boss_form_flashes` 번 고르게 뛴다(맞은 플래시와 같은 셰이더 · 전환 몫을 N 칸으로 나눠 칸마다 1 → 0).
- **HUD:** 보스 체력 바에 문턱 두 자리를 금으로 긋는다.
- 맞은 흰 플래시는 무적 동안 안 뛴다 — 무적이 보이게.

---

## 5. 테스트

- 바닥: 문턱을 넘는 칼 · 폭탄이 문턱에서 멈춘다 · 마지막 페이즈는 0 까지.
- 전환: 닿은 틱에 동작이 걷히고 무적 · 90틱 뒤 페이즈 2 · 바닥 400 · 무적이 풀린다 · 쉬기는 그 뒤부터.
- 무적: 칼 · 폭탄의 피해 0 · 경직 채움 0 · 로그 `shielded`.
- 같은 틱에 게이지로 무너져도 전환이 이긴다(탈진이 풀려 있다).
- 공중에서 전환하면 높이만 따라 내린다.
- 데이터: 문턱의 순서 · 범위 · 빠진 키.
- 기록 · 되살리기: `form_shifts` · `boss_start_health` 가 실리고 같은 판이 선다.
- 리플레이 골든이 체력 1200 으로 바뀐다 — PR 에 이유를 적는다.

---

## 6. 하지 않는 것

- 페이즈마다 다른 조종기 · 가중치(조각 7).
- 페이즈마다 다른 동작 · 수치. 세 페이즈는 같은 보스다.
- 전환 연출의 새 그림(idle 과 셰이더만 쓴다).
