# 내려찍기 단일 계열 보스전 — 설계

**상태:** 승인됨 (2026-09-24) · 구현 대상 이슈 #45 · #46 · #47

> ⚠ **이슈 #53 이 이 문서의 네 자리를 갈아엎었다.** 나머지(§0 계측 · §2 의 변종 뼈대 · §3 축)는 그대로 유효하다.
> - **§1.1** 탭 = 패리 / 홀드 = 가드는 **한 행동**이 됐다(누르면 방어 자세, 창 안이면 패리 · 밖이면 가드).
>   부정확 패리 단계는 사라졌다.
> - **§1.4** 가드 불가는 3단계만이 아니라 **아홉 변종 전부의 마무리**에 붙는다(유저 결정). 예고는
>   **빨강 + 危** 이고 빨강은 한 가지 뜻 — "가드로 못 막는다 = 받아쳐라" — 이다. 아래 표의 "호박 링 + 危" 는 옛 모양이다.
> - **§1.5** 경직은 하나뿐이고 마무리를 받아쳤을 때 걸린다(`finisher_parry_stagger` 2.3). 근거는
>   `overfit/data/bosses.json` 의 `_note_finisher_parry_stagger`.
> - **§2.3 · §2.4** `II-쐐기` 의 봉인은 스태미나가 아니라 **무게**(빨간 26)가 됐고, 스태미나 봉인은
>   `III-쐐기` 로 옮겼다(셋째 8 → 32 · 마무리 26 → 14 — 붙든 가드를 빨강 전에 깬다). 산수는
>   `overfit/data/patterns.json` 의 두 변종 `_note` 에 있다.

보스 패턴을 **내려찍기 하나**로 줄이고, 그 계열 안에서 단계별 변종을 만든다.
목적은 딥러닝 세로 슬라이스를 가장 짧게 세우는 것이다 — "회피 기록 → 변종 선택 → 다시 측정"이
한 바퀴 도는지를 패턴 하나로 먼저 확인한다.

이 문서는 세 각도(리듬 · 자원 · 기하)로 독립 설계한 뒤 다섯 렌즈(대시 · 간격 · 가드 · 기하 · 계측)로
구멍을 뚫어 나온 결과를 종합한 것이다.

## 0. 먼저 고쳐야 하는 것 — 지금 계측이 거짓말한다

**이 둘을 고치기 전에는 변종 선택이 성립하지 않는다.** 의존 봉인은 "이 사람이 무엇에 기대는가"를
읽는 데서 출발하는데, 그 읽기가 틀린다.

### 0.1 밖으로 한 대시가 `Spacing` 으로 기록된다

`HitResolver.Resolve` 의 순서는 **거리 → 높이 → 대시무적 → 패리** 다. 대시로 사거리를 벗어나면
거리에서 먼저 `MissedByRange` 로 빠지고, `BattleSim.Credit()` 이 그것을 `Verb=Spacing` 으로 붙인다.

산수: 유효 무적 = `min(dash_i_frames 0.14, dash_window)` → 8틱. 대시는 틱당 `2200/60 = 36.67px`.
서는 자리 `85 + 30 = 115` 에서 밖으로 나가면 `115 + 36.67k > 250` 은 **k = 4** 부터다.
즉 무적 8틱 중 **3틱만 `Dodged`** 이고 나머지 5틱은 `MissedByRange → Spacing` 이다.

**결과: 대시 의존자가 간격 의존자로 기록된다.** 2단계에서 정반대 변종이 뽑힌다.

> **고침:** `Credit()` 의 `MissedByRange` 갈래에서, 그 거리를 만든 것이 대시면 대시의 공으로 돌린다.
> `_dashStartedAt` 이 살아 있으면 `(Dash, _dashStartedAt)`, 아니면 `(Spacing, NaN)`.

### 0.2 `MissedByRange` 가 안과 밖을 뭉갠다

`distance < MinDistance || distance > MaxDistance` 가 한 갈래라, **파고들어 피한 것과 도망쳐
피한 것이 계측에서 같은 한 점**이다. 안쪽 주머니를 쓰는 변종을 만들면 그 학습이 안 잡힌다.

> **고침:** `HitVerdict` 를 `MissedByRange` → `MissedTooFar` · `MissedTooClose` 로 가른다.
> `DodgeVerb.Spacing` 은 그대로 두되 `DistanceBias` 가 둘을 반대 부호로 읽는다.

### 0.3 (자동 해결) `PlayerAxes.From` 이 `PatternId` 를 안 읽는다

열 축 전부가 모든 패턴을 뭉갠 값이다. 계열이 여럿이면 치명적이지만 **계열을 하나로 줄이는
이번 변경으로 사라진다.** 계열이 돌아오면 다시 살아나므로 주석으로 남긴다.

## 1. 가드

### 1.1 입력

키는 패리와 같다(`K`). `InputFrame` 에 레벨 한 칸 `ParryHeld` 를 더한다 — #40 의 `AttackHeld` 와 같은 모양이다.

```
K 누름(엣지)  ─▶ 패리 시도. 0.133 정확 / 0.5 부정확 창이 여기서 흐른다 (지금과 동일)
패리 동작(0.30s)이 끝났는데 아직 누르고 있다 ─▶ 가드 진입
K 놓음        ─▶ 가드 해제
```

**패리를 느리게 만들지 않는 것이 계약이다.** 홀드 판정을 기다렸다 패리를 시작하면 정확 창이 통째로 밀린다.

### 1.2 값 (전부 `fighters.json`)

| 키 | 값 | 근거 |
|---|---|---|
| `guard_chip_ratio` | 0.25 | 1단계 3연타를 다 막아도 7~8 (체력 110) |
| `guard_stamina_per_damage` | 1.8 | **피해에 비례한다.** 8피해 → 14 · 26피해 → 46. 무거운 타격이 가드를 깨는 것이 가드 퍼니쉬의 레버가 된다 |
| `guard_break_lock` | 0.9 | 붕괴하면 남은 타격을 그대로 맞는 길이 |
| 이동 | 불가 | 가드와 간격이 배타적이어야 선택이 된다. 봇도 단순해진다 |

스태미나는 `Idle` 일 때만 40/s 로 찬다 — **가드 중에는 안 찬다.**

### 1.3 가드 붕괴

두 가지로 깨진다.

1. 스태미나가 모자란 채로 막을 때
2. **가드 불가** 판정을 가드로 받을 때 — 스태미나가 남아 있어도 깨진다. 피해는 **전액**이다.

### 1.4 가드 불가

`PatternStep.guard_break: true` (판정 단위다 — 마지막 한 대에만 붙는다).
`PatternTags.has_guard_break` 는 망의 입력용 요약이고, 테스트가 둘의 정합을 대조한다.

**예고는 색이 아니라 기호다.** 붉은색은 이미 반대 뜻으로 차 있다.

```
붉은 링        ▶ 패리 불가 · 대시해라      (지금은 안 쓴다 — 점프 강타를 뺐다)
호박 링        ▶ 평범한 공격
호박 링 + 危   ▶ 가드 불가 · 받아쳐라
```

### 1.5 상 — 가드 불가를 정확 패리하면

보스 경직이 **0.5초 → 1.6초**. `bosses.json` 에 `guard_break_parry_stagger` 로 둔다.

1.6 + 패턴 간격 0.8 = 2.4초. 최대 차지(2.0833초)가 확실히 들어가는 길이다 —
"받아쳤다 → 제일 센 걸 꽂는다"가 한 동작으로 이어진다.

## 2. 내려찍기 계열

### 2.1 공통 — 3타 전 간격을 넓힌다

**2타와 3타 사이를 0.90초로 둔다.** 탭 공격은 0.4166초에 닿고 0.50초에 끝나므로 한 대가 들어간다.

이 간격은 **미끼이기도 하다.** 거기에 공격을 끼우는 습관이 3단계 `III-역습` 의 표적이다.

### 2.2 1단계 — 내려찍기 I (변종 없음)

이전 기록이 없으므로 하나뿐이다. **네 답이 전부 성립해야 한다** — 무엇에 의존하는지를 재는 단계이기 때문이다.

| | |
|---|---|
| 판정 | **0.85 / 1.40 / 2.30** (선딜 0.85 · 간격 0.55 · **0.90**) |
| 범위 | `[0,250]` `[0,250]` `[0,270]` × 높이 `[0,340]` |
| 피해 | 8 / 8 / 14 |
| 태그 | `dash_window 0.20` · `parry_window 0.18` · `jumpable false` |

**왜 느려졌나 (지금은 선딜 0.50 · 간격 0.35)**

- 간격 0.35 는 `parry_lock`(0.6초, 틱으로 37틱 = 0.6167)보다 **짧다.** 한 번 늦게 누르면 다음 판정에
  손이 묶인 채로 맞고, 연타 징벌(정확 창 7틱 → 5틱 → 0)까지 겹쳐 **실수 하나가 세 번 벌을 받는다.**
- 선딜 0.50 은 `feel.tell_lead_seconds`(0.9)보다 짧아, 패턴이 시작할 때 예고가 이미 44% 크기로
  튀어나온다. 커지는 곡선의 절반이 잘려 "무엇이 오는지"를 말할 시간이 없다. 0.85 면 94% 가 돈다.

**네 답의 가격** — 대시 75 · 가드 53(14+14+25) · 패리 45 · 간격 0. 전부 스태미나 100 안에 든다.

### 2.3 2단계 — 세 변종, 하나를 고른다

원칙: **저격 대상이 아닌 사람에겐 1단계와 같은 난이도여야 한다.** 봉인이지 벌이 아니다.

| 변종 | 노리는 것 | 판정 | 바뀌는 것 |
|---|---|---|---|
| **II-끌기** | 대시 의존 | 0.85 / 1.40 / **2.45** | 3타를 **밀고** 그 자리를 `[290,620]` 로 — **대시 착지점**이다(115 + 367 = 482). 붙어 있으면 안쪽 290 미만이라 무해. `feint: true` |
| **II-쇄도** | 간격 의존 | 0.85 / 1.40 / 2.30 | 3타 사거리 `[0,900]`. 아레나 1920 에서 도주로를 덮는다. 붙어 싸우면 어차피 안쪽이라 무관 |
| **II-쐐기** | 가드 의존 | 0.85 / 1.30 / 1.75 / **2.65** | 판정 넷, 마지막이 **26피해**. 가드 비용 = 14+14+14+46 = **88** → 붕괴. 패리는 60 이라 여전히 싸다 |

### 2.4 3단계 — 다섯 변종, 마지막은 전부 가드 불가

| 변종 | 노리는 것 | 형태 |
|---|---|---|
| **III-역린** | **패리** | `kind: "feint"` — 예고만 하고 판정이 없는 헛스윙. 거기 패리를 지르면 연타 사슬이 걸려 정확 창이 좁아지고, 진짜 판정이 그 뒤에 온다 |
| **III-끌기** | 대시 | II-끌기 + 마지막 가드 불가 · `dash_window 0` |
| **III-쇄도** | 간격 | II-쇄도 + 마지막 가드 불가 · 사거리 `[0,1800]`(방 전체) |
| **III-쐐기** | 가드 | II-쐐기 + 마지막 가드 불가 |
| **III-역습** | **욕심** | 2타 뒤 0.90 간격에 판정을 하나 끼운다(공격이 닿는 0.4166 직후). `punish_greed: true` |

**숨통은 변종 자체로 준다.** 못하는 사람에게 도망갈 구멍이 있는 변종을 주는 것이
"매 단계 넘을 수 있는 하나를 보장한다"의 실제 모습이다.

### 2.5 3단계 변종 선택 (나중)

유저가 **가장 많이 쓴 회피 수단 두 가지**를 고르고, 내려찍기 차례마다 그 둘 중 하나를 무작위로 쓴다.

**지금은 안 만든다.** 먼저 전 변종이 무작위로 재생되는 1패턴 보스전을 완성한다.

## 3. 죽는 축과 남는 축

점프 강타와 이단 올려베기를 빼면 축 다섯이 근거를 잃는다.

| 축 | 누가 들고 있었나 | 이후 |
|---|---|---|
| `airborne_at_impact` | 점프 강타의 대공 판정 | **죽는다** |
| `jump_reliance` · `jump_timing_bias` | 이단 올려베기(유일한 `jumpable`) | **죽는다** |
| `distance_bias` | 점프 강타의 안쪽 주머니 | **II-쇄도 · III-쇄도**가 이어받는다 |
| `dash_direction_bias` | 점프 강타만 `in` | **II-끌기**가 밖으로 대시를 잡는다 |
| `dash_timing_bias` · `dash_timing_var` · `parry_rate` · `parry_reliance` · `greed` | 내려찍기도 들고 있었다 | 산다 |

**축을 지우지 않는다.** 표본이 없으면 0 이고 `Samples` 가 그 얇기를 같이 나른다 —
계열이 돌아오면 다시 살아나야 하므로 정의는 남기고 그 사실을 주석에 적는다.

가드는 새로 재야 한다: `DodgeVerb.Guard` · `HitVerdict.Guarded` · `HitVerdict.GuardBroken`.
축을 11번째로 늘릴지, `ParryLateSamples` 처럼 **개수로만 실을지**는 구현에서 정한다 —
10축 계약을 깨는 것은 망의 입력 모양을 바꾸는 일이라 가볍지 않다.

## 4. 구현 순서

1. **#45** 계측 두 곳을 고친다 (0.1 · 0.2). 이게 먼저다 — 틀린 신호 위에 변종을 얹으면 학습이 처음부터 잘못 돈다.
2. **#46** 가드 메커니즘 (입력 계약 · 규칙 · 붕괴 · 가드 불가 · 危 예고 · 연장 경직).
3. **#47** 내려찍기 단일 계열로 전면 교체 (다른 두 패턴 제거 · 변종 아홉 · 3단계 명부 · 무작위 재생).

## 5. 남은 결정

- 가드를 **축**으로 올릴지 개수로만 실을지 (10축 계약)
- `kind: "feint"` 를 타임라인 종류로 새로 만들지, `damage: 0` 판정으로 흉내 낼지
  (후자는 "맞지 않았다"가 이벤트로 남아 계측이 오염된다 — 전자를 권한다)
- 3단계 사거리 `[0,1800]` 이 실제로 방 전체인지는 보스 위치에 달렸다. 아레나 1920 · 보스가 중앙이면
  최대 거리는 약 930 이다 — 구현에서 실제 스폰 위치로 확인할 것
