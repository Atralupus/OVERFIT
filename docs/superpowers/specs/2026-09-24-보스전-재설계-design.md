## 0. 왜 다시 짜나

v0.6.0 을 직접 해본 유저의 결정이다. 줄이면 셋이다.

1. **링 연출이 별로다.** 공격이 동그라미로만 말한다. 보스 모션이 예고여야 한다.
   (2026-09-26 · #81) 보스 공격의 링은 이제 없다. 캐릭터의 링은 남긴다 — 유저가 그렇게 좁혔다(§1 ⑤).
2. **판정이 그림과 따로 논다.** 지금 판정은 "보스 중심에서 거리 몇~몇, 높이 몇~몇" 인 좌우 대칭 띠인데,
   그림의 칼은 앞으로 휘두르고 어떤 궤적은 등 뒤까지 감는다. **보이는 것이 곧 맞는 것**이어야 한다.
3. **범위를 줄인다.** 1단계, 패턴 둘을 먼저 완성한다.

### 2026-09-26 — 보스를 두 단계로 다시 세운다

1 · 2번 PR 이 들어간 뒤 유저가 구조를 바꿨다(§1). 줄이면 넷이다.

4. **옛 변종 아홉을 걷는다.** 남는 것은 그림의 프레임에 맞춰 만든 패턴뿐이다.
5. **보스는 두 단계다.** 1단계를 이기면 2단계, 2단계를 이기면 클리어다. 지면 같은 단계를 다시 한다.
6. **재시도마다 다른 보스.** 지금은 시드가 51 로 고정이라 몇 번을 다시 해도 같은 순서다. 시도마다 시드를 새로 내고,
   패턴 고르기는 그때까지의 기록을 받는 인터페이스를 탄다 — 망이 들어올 자리다. 지금 구현은 무작위 하나다.
7. **2단계 패턴은 1단계의 습관을 겨냥한다.** 1타 → 돌진 → 3타 · 1타 → 잡기 · 점프 ×3 · 엇박 3연격.

**그대로인 것:** 2연격 · 패리의 커밋과 되받아치기 · 가드 · 대시 · 10축 계측 계약(§7) · 결정론(같은 시드면 같은 결과 — CLAUDE.md §4) ·
로그 형식(CLAUDE.md §5).

### 성공의 기준

- 보스의 칼 궤적이 보이는 자리에 서 있으면 맞고, 안 보이는 자리(초승달 안쪽 포함)에 있으면 안 맞는다.
- 두 단계 보스전이 보스 공격의 링 없이 모션만으로 읽힌다 — 그 링은 #81 에서 빠졌다. 캐릭터의 링(가드 · 패리 · 붕괴 · 공격 섬광)은
  남는다(유저 · 2026-09-26 · §1 ⑤).
- 가드(↓)와 패리(K)가 다른 선택이다 — 가드는 싸고 안전하고, 패리는 틀리면 맞지만 맞히면 보스가 탈진해 반격 창이 열린다.
- 1단계를 이기면 2단계, 2단계를 이기면 클리어다. 지면 같은 단계를 **새 시드로** 다시 한다 — 순서는 대개 달라진다
  (패턴 둘인 명부면 첫 패턴이 같을 확률이 1/2 다 · §4).
- 2단계 패턴 넷이 저마다 겨냥한 습관을 가진 사람을 실제로 잡는다 — README 의 GIF 가 그 증명이다 (5번 PR).
- 패턴을 고르는 자리가 인터페이스 하나이고, 망은 구현 하나를 더해 들어온다.
- 사람과 봇이 같은 입력 통로로 이 전부를 낼 수 있다.

### 대화로 정한 것

- 패리에 성공하면 **보스 연격이 그 자리에서 끊긴다.**

- 패리에 실패하면 **그냥 맞는다.**
- 점프 공격은 **플레이어를 향해** 뛰어든다.
- 판정 모양은 **흰 픽셀을 격자로 떠서** 저장한다 (§3).
- (#71) **탈진은 하나다.** 패리로든 경직 게이지로든 같은 상태 · 같은 그림이다. 탈진하면 게이지를 비우고,
  탈진 동안 맞으면 피해만 들어간다.

  줄어드는 것(§4.3)을 받아들였다 — 받아친 쪽이 더 커진다.

  헛친 패리는 커밋과 경직 내내 J 까지 버린다. 경직 중에 맞은 판정은 그 패리의 시도다(§5.3 · §12).

### 가정한 것 — 틀리면 여기를 고친다

- 가드에 `↓` 와 함께 **`S`** 도 건다. 이동에 `A`·`D` 가 있어 짝을 맞춘다.
- 가드는 **땅에서만** 된다. 공중 가드는 없앤다.
- 공격 · 패리는 **끝까지 커밋**한다. 그동안 가드 · 패리 · 대시 · 이동이 전부 안 된다.
  가드는 커밋이 아니다 — 가드 중에 공격 · 패리 · 대시로 바로 넘어갈 수 있다.
- 보스가 **탈진할 때** 짧은 히트스톱과 흔들림이 난다. 연격이 끊기므로 박자를 밀 일이 없다.
  3번 PR 에서는 그 7프레임 동안 누른 키가 지금처럼 버려지고, 4번 PR 이 버리지 않게 한다.
- **대시 무적은 모든 판정에 공통이다** — 판정이 스스로 끄지 않는 한(잡기 · §4.7). 다만 바닥 전체 띠는 창 8틱 내내
  몸에 닿으므로, 무적 8틱이 창을 다 덮으려면 창이 열리는 **바로 그 틱**에 눌러야 한다(§4.2). 점프 공격의 실제 답은 가드와 점프다.
- 가드 수치(칩 25% · 스태미나 1.8배 · 붕괴 1.1초)는 **v0.6.0 그대로.** 붕괴의 1.1초는 4번 PR 부터 파이터의 **탈진**이다(§5.5).

## 3. 판정 모양 — 그림에서 뽑아 JSON 으로

### 3.1 왜 격자인가

| 방법 | | |
|---|---|---|
| **흰 픽셀 격자 (채택)** | 초승달 안쪽의 빈 곳이 비어 있다 | 칸 크기를 골라야 한다 |
| 사각형 3~5개 근사 | 데이터가 작다 | 초승달의 빈 곳을 일부 메운다 |

### 3.2 도구 — `tools/extract_hitboxes.py`

- 입력: 설치된 에셋 `overfit/assets/<팩>/<애니>.png` (저장소에 없다 — `tools/install_assets.py` 를 먼저 돌린다).
- 판정 프레임 하나에서 **궤적 픽셀 = 순백**(불투명도 > 200, R·G·B 가 전부 255 — `white_min` 254)을 모은다.
  잰 값이다: 궤적은 전부 `#FFFFFF` 이고 왕의 흰 털깃·수염은 전부 `#F5EEEE` 다. 처음 기준(> 235)은 둘을 같이 세서
  `attack3` f2 의 초승달 안쪽 — 보스를 끌어안으면 안 맞아야 하는 자리 — 에 수염이 사각형을 세웠다(최종 리뷰).
- **4×4 원본 픽셀을 한 칸**으로 떠서, 칸 안 궤적 픽셀이 25% 이상이면 그 칸을 판정으로 친다.
  보스 배율 5.5 에서 한 칸은 월드 22px, 플레이어 2.5 에서 10px 이다 — 플레이어 몸통(60×120)보다 충분히 잘다.
- 같은 줄에서 이어진 칸은 **가로로 합쳐** 사각형 하나로 만든다. 데이터가 작아지고 로그로 읽힌다.
- **배율은 `balance.json` 의 `feel.*_sprite_scale` 에서 읽는다.** 뷰가 그리는 크기와 판정 크기가 따로 놀지 않게 하기 위해서다.
  어느 팩이 보스이고 파이터인지는 `bosses.json` · `fighters.json` 의 `sprite` 가 말한다.
- **기준점은 `.tres` 의 `region` 이다** — 원본 프레임이 아니다. `install_assets.py` 가 팩 전체의 불투명 범위로
  세로를 잘라 두었고(보스 2..105 · 플레이어 53..122) 뷰는 그 region 을 그린다. **region 의 아래끝이 발바닥(높이 0)**,
  **가로 가운데가 몸 중심**이다. 원본 프레임의 아래끝을 바닥으로 잡으면 보스는 33px, 플레이어는 195px 어긋난 자리에 판정이 선다.
- 판정 id 는 **`팩/애니메이션/프레임`** 이고 애니메이션 이름은 **`.tres` 의 이름**이다 — 시트 파일 이름(`attack1.png`)이 아니라
  뷰가 부르는 이름(`attack`). 보스 `attack` · `attack2` · `attack3`, 플레이어 `attack` · `attack2`.
- 같은 입력이면 같은 출력이다 (정렬 · 반올림 규칙을 고정한다).

### 3.3 출력 — `overfit/data/hitboxes.json` (**커밋한다**)

```jsonc
{
  "_comment": "...",
  "_source": { "cell_px": 4, "white_min": 254, "alpha_min": 200, "fill_min": 0.25 },
  "medieval_king/attack/2": {
    "scale": 5.5, "region": [320, 2, 160, 103],   // .tres 의 region 그대로 — 어느 픽셀에서 뽑았나
    "rects": [ [x0, x1, y0, y1], ... ]            // 공격자 기준 · 월드 px · x 는 보는 쪽이 +
  },
  ...
}
```

**뽑을 목록은 이 파일의 키다.** 새 판정 모양이 필요하면 키를 하나 더하고 도구를 돌린다.

실측 (4px 칸 · 채움 25%):

| id | 사각형 | 가로 | 높이 |
|---|---|---|---|
| `medieval_king/attack/2` | 13 | −110 ~ +396 | 38.5 ~ 236.5 |
| `medieval_king/attack2/2` | 23 | −352 ~ +440 | 0 ~ 346.5 |
| `medieval_king/attack3/2` | 30 | −286 ~ +418 | 0 ~ 566.5 |
| `martial_hero/attack/4` | 18 | −40 ~ +230 | 2.5 ~ 172.5 |
| `martial_hero/attack2/4` | 16 | −40 ~ +240 | 12.5 ~ 132.5 |

- 좌표는 **공격자 기준**이다. x 는 몸 중심에서 보는 쪽이 +, y 는 발바닥에서 위로. 공격자가 뒤돌면 x 만 뒤집는다.
- 테스트가 이 파일에 대해 지킨다: 비어 있는 모양이 없다 · 사각형이 뒤집혀 있지 않다 · 기록된 배율이 `balance.json` 과 같다.
- **PNG 는 커밋하지 않는다.** `git ls-files overfit | grep -c '\.png$'` 는 0 을 유지한다.

**그림에서 뽑지 않는 모양 — 바닥 띠.** 점프 공격의 착지(§4.2)와 잡기(§4.7)는 궤적이 아니라 바닥 전체다.
이 파일은 도구가 쓰는 파일이라 여기 안 넣고, 타임라인 단계에 `band: [안쪽, 바깥쪽, 아래, 위]` 로 적는다(§8.1) —
옛 좌우 대칭 띠(`HitShape.Band`)와 같은 모양이고 같은 통로를 탄다.

### 3.5 판정 규칙

한 번 휘두르는 것(= 판정 한 장)은:

1. **궤적 프레임이 떠 있는 동안 내내 살아 있다.** 판정 프레임에 들어서는 한 틱에만 물으면
   흰 궤적이 눈앞에 보이는데 두 틱 뒤에 걸어 들어간 사람이 안 맞는다.
2. 매 틱 상대 몸통이 사각형 중 하나라도 겹치는지 본다. 겹치면:
   - 대시 무적 중이고 이 판정이 무적을 받으면 → 이 틱은 넘어간다 (**창이 끝나기 전에 무적이 풀리면 그 뒤 틱에 맞는다** — 다크소울과 같다)
   - 패리 창 안이고 이 판정이 패리를 받으면 → **패리** · 이 휘두름 끝 · 보스 탈진 (§4.3)
   - 가드 중이고 이 판정이 가드를 받으면 → **가드** 또는 **가드 붕괴** · 이 휘두름 끝
   - 아니면 → **맞음**(붙드는 판정이면 **잡힘** — §4.7) · 이 휘두름 끝
3. **한 번 휘두르면 한 번만 맞는다.**
4. 창이 닫힐 때까지 한 번도 안 맞았으면 관측 **하나**를 남긴다 — 어느 틱에 무적이 먹었으면 `Dodged`,
   아니면 **창이 열린 틱**에서 계산한 빗나간 이유다 (§3.6 ① · §7).
5. **끊긴 창은 관측을 안 남긴다.** 보스가 탈진해 패턴이 끊기거나(§4.3) 판이 끝나 창이 안 닫힌 채 남으면(§3.6 ③),
   그 판정은 스트림에 아무것도 안 남기고 로그 한 줄 `[boss][D] cut_swing id=… tick=… reason=exhaust|end` 만 남긴다.
   끊긴 창에는 결과가 없다. 지어내면 창이 열린 첫 틱의 빗나간 이유(대개 거리)가 그대로 나가, 모양 안에 서 있던 사람도
   "거리로 빗나갔다" 로 계측에 들어간다. 그 거짓 관측이 간격 축과 대시의 공으로 번지고, 뷰도 관측이 늘면 판정 순간의 번쩍임과 흔들림을 건다(판정 충격파는 #81 로 걷었다).
   같은 틱의 순서는 **보스 판정 → 파이터의 칼 → 끊기**다 — 파이터가 보스를 무너뜨린 틱(4번 PR)에 보스의 칼이 닿았으면 파이터는 맞는다.
6. **보스는 판정 창 동안 움직이지 않는다.** 도약 · 돌진(§4.2 · §4.6)은 창 밖에서만 돈다 — 데이터 테스트가 막는다.
   그래서 모양을 놓는 자리(보스의 X · Y · 보는 쪽)를 틱마다 한 번 잡는 지금 구조로 충분하다(#59 넘김 6).

**틱 반올림은 한 곳에서 정한다.** 8fps 한 장은 0.125초 = 7.5틱이다. 창은 초로 적고 `t_start ≤ t < t_start + dur`
로 비교한다 — 60Hz 에서 0.85초 시작이면 51~58틱, 8틱이다. 타임라인의 시각도 불러올 때 한 번 틱으로 바꾼다(§3.6 ⑤).

### 3.6 창이 한 틱보다 길 때 — #59 에 남은 결정 (3번 PR)

1번 PR 이 창을 여러 틱으로 늘리면서 미뤄 둔 것들이다(#59 의 1/4 넘김). 다섯 모두 §3.5 5 의 "끊긴 창은 관측이 없다" 와 맞춘다.

**① 관측은 어느 틱을 말하는가.**
- **결과를 가른 틱**이 관측의 몸(판정 · 수단 · 공중 · 거리 · 욕심)을 정한다: 닿았으면 닿은 틱, 무적이 먹었으면 처음 먹은 틱,
  빗나갔으면 **창이 열린 틱**. 우선순위는 닿음 > 무적 > 빗나감이다 — 창 안 어느 틱에 닿으면 앞의 빗나감은 버린다.
- **타이밍 오차의 기준은 결과와 무관하게 창이 열린 틱**(칼이 선 틱)이다.
- 이유: 빗나감을 닫히는 틱에 재면, 창 안에서 대시가 끝난 사람이 `Spacing` 으로 적힌다 — #46 이 고친 편향이 돌아온다.
  열린 틱에 재면 창이 한 틱이던 때와 같은 자리를 잰다. 오차의 기준이 결과마다 다르면 대시 · 점프 · 패리의 오차가 서로 다른 자로
  잰 값이 된다. 기준을 칼이 선 틱으로 두면 "칼이 선 뒤에 눌렀다" 가 양수로 남는다 — 전에는 구조상 양수가 없었고,
  이제 뜻 있는 값이다(`DodgeEvent.TimingError` 의 주석을 같이 고친다).

**② 띠가 아닌 모양의 빗나감.**
- §7.1 의 외곽 상자 규칙을 그대로 쓴다: 가로 범위 밖이면 `MissedTooFar`, 가로로는 안인데 세로로 모양 전체의 위나 아래면
  `MissedByHeight`, 둘 다 안인데 빈 칸이면 `MissedByGap`. 순서는 가로 → 세로 → 틈이다.
- **보스 등 뒤라도 모양의 뒤끝 밖이면 `MissedTooFar` 다.** `왼쪽을_보는_보스의_모양은_왼쪽을_친다` 가 단언하는 대로 둔다.
- 이유: 거리 축(`DistanceBias`)은 **부호로 모양 안 · 밖을, 크기로 |dx| 를** 싣는다. 등 뒤 150px 에서 빗나간 것은 이미 +150 이라
  가깝게 읽힌다 — 따로 갈래를 둘 근거가 계측에 없다. 등 뒤를 틈으로 치면 "초승달을 끌어안았다" 와 "보스를 돌아 나갔다" 가 한 점이 된다.
  세로가 틈보다 먼저인 것은 **모양 전체의 위나 아래**일 때뿐이라, 초승달 구멍 안의 공중은 틈이다.
- **몸 높이의 끝으로 한 번 더 가른다** (#72 계획 결정 30). 실제 궤적은 높이마다 끝이 달라서, 외곽 상자로만 가르면 2 · 3타의 사거리
  바로 밖(예: +427 ~ +470)이나 외곽 상자 안의 등 뒤가 `MissedByGap` 으로 떨어져 간격을 둔 사람이 음수(안쪽)로 실린다. 그래서 가로 → 세로 뒤에,
  **몸 높이에 걸친 사각형들의 가로 범위**를 잰다. 몸이 그 앞끝 너머이거나, 보스 중심 뒤이면서 그 뒤끝 너머면 `MissedTooFar` 다.
  남는 틈은 몸 높이의 궤적 사이와 품 안뿐이다. 땅에서는 3타의 초승달 안쪽(−30 ~ +79) 하나다.

**③ 판이 끝날 때 열린 창** — 버린다(§3.5 5 · `reason=end`). 판을 끝낸 그 한 대는 닿은 것이라 관측이 있고,
남은 창에는 결과가 없다. 그 판의 관측은 곧 시도 기록(§4.4)이 되므로 여기서 지어낸 한 줄이 망의 입력으로 간다.

**④ 봇이 살아 있는 창을 보는 법.** `BattleSim.SwingLive` — 살아 있는 보스 판정이 있나. 봇은 창이 살아 있는 동안을
"판정이 지금" 으로 본다: 가드로 받기로 한 패턴이면 ↓ 를 붙들고, 칼질을 새로 누르지 않는다.
이유: `NextActiveIn` 은 판정이 서는 틱에 "다음 판정" 이기를 그쳐, 봇이 8틱 창의 첫 틱에 가드를 풀고 남은 틱에 맞았다.

**⑤ 판정 시각을 정수 틱으로.** 러너의 시계는 1/60 을 더해 가지 않고 **틱을 센다.** 단계의 시각 T 는 불러올 때 한 번
`round(T × 60)`(0 에서 먼 쪽 — `TicksFor` 와 같은 규칙)으로 바꾸고, 러너의 틱 수가 그 값에 닿는 틱에 그 단계에 든다
(T = 0 인 첫 단계는 러너의 첫 틱이다).
- 지금은 부동소수 누적 때문에 1.55초 판정이 93틱이 아니라 94틱에, 2.65초가 159틱이 아니라 160틱에 선다(0.85초는 51틱 그대로).
  고치면 골든이 움직이므로 판이 통째로 바뀌는 3번에서 한다.
- **판정 단계의 시각은 정수 틱이어야 한다** — 반 틱이면 반올림이 창을 한 틱 밀어, 창이 다음 장으로 넘어간 뒤까지 산다.
  데이터 테스트가 막는다: 판정 단계의 T × 60 은 정수이고, 다음 단계의 틱은 창이 닫힌 뒤다. 그림 장의 경계(0.725 = 43.5틱 같은)는
  반 틱이어도 된다 — 뷰가 규칙의 단계를 그리므로(§6) 그림과 판정은 여전히 같은 틱에 바뀐다.
- 쉬는 간격(`pattern_gap`)과 탈진도 틱으로 센다 — 0.8초 = 48틱, 1.5초 = 90틱.

## 4. 보스

**보스는 두 단계다 — 두 번의 전투다.** 1단계를 이기면 2단계가 열리고, 2단계를 이기면 클리어다.
지면 같은 단계를 다시 한다 — 시도마다 시드가 새로 나오므로 패턴 순서가 **대개** 달라진다(§4.4). 명부가 둘이면
두 시도의 첫 패턴이 같을 확률이 1/2, 처음 k 개가 다 같을 확률이 1/2^k 다 — 바뀌는 것은 시드이고 순서는 그 결과다.

| 단계 | 명부 (`stages.json`) | want | 고르기 | 뜻 |
|---|---|---|---|---|
| 1 | `3연격` · `점프 공격` | 2 | `uniform` | **재는 자리.** 대시 · 가드 · 패리 · 간격 · 점프가 다 쓰인다 |
| 2 (3 · 4번 PR) | 1단계와 같다 | 2 | `uniform` | 5번 PR 전까지는 자리만 있다 |
| 2 (5번 PR~) | `3연격` · `점프 3연속` · `1타 돌진` · `1타 잡기` · `엇박 3연격` | 5 | `uniform` → 망 | 1단계의 습관을 겨냥한다 (§4.6 ~ §4.9) |

- 2단계를 이기면 결과 화면이 **클리어**이고 [처음부터] 가 1단계로 돌린다(단계 1 · 시도 기록 비움 — §4.4).
  흐름은 지금 코드 그대로다 — 다음 단계가 정의돼 있지 않으면 클리어다. 이긴 화면의 "다음 단계는 패턴이 늘어난다" 는 거짓이 되므로 고친다.
- **3단계는 없다.** 디버그 키는 `1` · `2` 뿐이다(`project.godot` 의 `debug_stage_3` 을 지운다 · 타이틀의 안내 주석과
  `CONTRIBUTING.md` 의 키 표도 같이). 투어의 단계 점프는 가장 먼 단계인 2로 가고, 스모크가 `to=2` · `battle ready stage=2` 를 본다.
- 패턴 id 에 `×` 나 화살표를 안 쓴다 — 로그의 `key=value` 를 손으로 치고 grep 하는 자리라서다. 글에서는 "1타 → 돌진 → 3타" ·
  "1타 → 잡기" · "점프 ×3" 으로 부른다.
- 2단계 명부는 5번 PR 이 **통째로** 바꾼다. `stages.json` 의 "새 것은 맨 뒤에" 규칙은 같은 설계 안에서 뽑기 좌표를 지키려는 것이고,
  이것은 설계가 바뀌는 자리다. 골든은 1단계로 돌아(§9) 안 움직인다.
- 1타로 여는 세 패턴(3연격 · 1타 돌진 · 1타 잡기)은 **1.30초까지 한 틱도 다르지 않다.** 1.30초에 3연격은 `attack2` 를 들고,
  돌진은 달리고, 잡기는 `idle` 로 선다 — "1타 뒤에 무엇이 오나" 가 그 순간에 읽힌다. 엇박 3연격은 0.725초에 갈린다 —
  3연격이면 칼이 오르는(f1) 장에서 엇박은 칼을 든 f0 에 더 선다(§4.9).

### 4.2 패턴 B — 점프 공격 (3번 PR)

| 시각 (초) | 틱 | 그림 | |
|---|---|---|---|
| 0.00 ~ 0.40 | 1 ~ 23 | `jump` f0 | 웅크린 자세 = 예고 |
| 0.40 | 24 | 도약 | **이 틱의 플레이어 자리를 향해** — 그쪽으로 돌아선다. 그 뒤로는 안 따라간다 |
| 0.40 ~ 0.75 | 24 ~ 44 | `jump` f1 | 상승 |
| 0.75 ~ 1.00 | 45 ~ 59 | `attack3` f0 → f1 | 공중에서 휘두르기 시작 |

- 공중 궤적은 **포물선을 식으로** 그린다 — `y = 4H·s(1−s)`, `H = 280px`, `s = (틱 − 24) / 36`. 가로는 s 에 비례해 곧게 간다.
  물리 적분이 아니라 식인 이유는 착지가 **정확히 60틱**이어야 하기 때문이다 — 도약 틱 24 에서 s = 0, 60틱에서 s = 1 이다.
  적분하면 반올림이 착지를 한 틱씩 흔든다.
- 착지 자리는 **도약 틱의 플레이어 X 에서 보스 쪽으로 몸 둘 폭(85 + 30 = 115)만큼 앞**이다. 아레나 안(85 ~ 1835)으로 자른다.
  플레이어와 보스가 같은 X 면 보던 쪽을 쓴다.
- **도약하는 틱에 착지 자리 쪽으로 돌아선다.** 패턴 중에 방향이 바뀌는 유일한 자리다. 예고가 거짓말이 되지 않는다 —
  착지 판정이 좌우 대칭인 바닥 전체라 방향이 판정을 안 바꾼다. 안 돌면 등 뒤로 날아가는 그림이 된다.
- 착지 판정은 **바닥 전체**다 — 데이터로 `band: [0, 1920, 0, 60]` (보스 중심에서 0 ~ 1920 · 좌우 대칭 · 높이 0 ~ 60).
  보스가 어디(85 ~ 1835)에 내려도 [X − 1920, X + 1920] 이 바닥 [0, 1920] 을 덮는다. 그림에서 뽑지 않는다 — 유저가 "지면 전체" 라고 했다.
- **패리 불가.** 가드 · 점프로 피한다.
  - **점프:** 창 8틱 내내 발이 60 위에 있어야 한다. 이산 점프(`jump_velocity` 1220 · 중력 2400 · 1/60초)는 누른 틱부터 60틱(1.000초)
    떠 있고, 그중 53틱(0.883초 · 누른 틱 + 3 ~ + 55) 동안 발이 60 위다. 그래서 창이 열리기 **3 ~ 48틱 전**(46틱 · 0.767초)에 누르면 넘는다.
    겹침은 가장자리도 치므로(`HitRect.Overlaps`) 발이 60 과 같으면 맞는다.
  - **가드:** 12 × 1.8 = 21.6 스태미나 · 칩 3.
  - **대시:** 무적 8틱(누른 틱 ~ + 7)이 창 8틱을 다 덮어야 하므로 창이 열리는 **바로 그 틱**에 누른 대시만 산다. 한 틱이라도 이르면
    무적이 풀린 다음 틱에 맞는다 — 바닥 전체라 대시로 벗어날 곳도 없다. 규칙은 막지 않는다(§1 가정).
- 보스는 공중에서 몸통도 같이 올라간다. 파이터 칼(윗끝 172.5)은 보스 발이 172.5 위인 동안(s ∈ 0.19 ~ 0.81, 0.37초) 안 닿는다.
  그 밖은 그 자리의 기하가 정한다.
- 도약은 **움직임** 하나다(§8.1): 도약 단계에 `motion: { "id": "leap", "height": 280, "air": 0.60 }` 을 단다.
  데이터 테스트가 도약 시각 + `air` = 착지 판정 시각인지 본다. `fall` 은 안 쓴다.
- 공중에서 탈진하면(4번 PR — 게이지): 착지 판정 없이 포물선의 높이를 그대로 따라 그 자리에 내린다(가로는 멈춘다).
  받아칠 수 없는 이 패턴을 멈추는 길은 게이지뿐이다.

### 4.3 탈진 — 패리 (3번 PR) · 경직 게이지 (4번 PR)

원인은 둘이고 **루틴은 하나다**(`BattleSim` 의 탈진 루틴 하나). 둘이 같은 상태에 닿아야 유저가 말한 "패리당했을때와 동일하게" 가 선다.

| 원인 | 언제 | PR |
|---|---|---|
| 패리 | **어느 타든** 받아쳤다. 패리를 안 받는 판정(점프 공격의 착지 · 잡기)은 받아칠 수 없다 | 3 |
| 경직 게이지 | 파이터의 칼이 게이지를 끝까지 채웠다 (§4.5). 보스가 무엇을 하고 있었든 — 선딜 중이든 창이 열려 있든 쉬는 중이든 공중이든 | 4 |

탈진하면:

- **하던 패턴이 그 자리에서 끊긴다.** 남은 타격 · 돌진 · 잡기는 안 온다. 열린 보스 판정은 관측 없이 버린다 (§3.5 5).
- 보스는 `hit`(take-hit · **`hit_white` 아님**)를 **제 속도**(10fps · 0.4초)로 한 번 돌고 마지막 장에 선 채 **푸른 톤으로 1.5초**
  (`exhaust_seconds`) 있다. 무너지는 순간 화면이 흔들리고 히트스톱이 걸린다 — 길이는 `feel.hitstop_frames`(7프레임)다.
- 탈진은 **틱으로 센다** — 1.5초 = 90틱. 틱 수는 `BattleSim` 이 바꿔 넘긴다(보스는 `BattleSim` 을 모른다).
- 탈진이 끝나면 **패턴 간격(0.8초 · 48틱) 뒤** 다음 패턴을 고른다. 쉬는 중에 무너져도(4번 PR) 간격을 처음부터 센다.
- 탈진 동안 맞으면 **피해만** 들어간다. (4번 PR) 게이지는 무너질 때 비고, 탈진 동안에는 안 찬다(줄지도 않는다) —
  풀리자마자 다시 무너지는 연속 탈진이 없다.
- 탈진 중에 또 탈진할 길은 없다(판정도 채움도 없다). 오면 규칙 위반이다 — `[boss][E] exhaust_reentry`.
- 로그: `[boss][D] exhaust cause=parry|poise id=<패턴> tick=…`.
- 3번 PR 의 그림: 평타 피격은 아직 `hit_white` 다(흰 플래시는 4번 PR). 탈진한 보스를 때리면 `hit_white` 가 0.4초 돌고 탈진 자세로 돌아온다.

**1.5초의 근거** — 반격 2연격이 확실히 들어가는 길이다.

```
패리 성공 ─┬─ 반응          ~0.20
           ├─ 1타 닿음       0.28   (반응 + 선딜 0.083)
           └─ 2타 닿음       1.12   (+ 1타 0.25 + 2타 선딜 0.667)
탈진 끝       1.50           2타가 창의 첫 틱에 닿으면 반응이 0.58초까지 늦어도 들어간다
```

받아친 패리의 커밋 안에서 누른 J 는 곧장 1타다(되받아치기 · 2번 PR) — (#82) 커밋 뒤의 패리 뒤 경직 안에서도 그렇다. 그래서 패리 뒤
경직이 이 산수를 안 민다. 가장 이른 J 는 받아친 다음 틱이라, 반응 없이
0.0167 + 0.25 + 0.6667 + 0.1667 = 1.1001초이고 1.5 − 1.1001 = 0.3999 가 남는다 — `BossDataTests` 가 반응 여유 0.15 를 넣어 못박는다.

둘은 같은 산수의 두 끝이다. 받아친 틱에서 반응 r 뒤에 J 를 누르면 2타의 창은 r + 0.9167 ~ r + 1.0834 다.
- **보통** — 2타가 창의 **첫 틱**에 닿는다(보스가 칼 안에 서 있다): r + 0.9167 < 1.5 → r < **0.583**. 그림의 0.58 이다.
- **가장 나쁜 경우** — 창의 **끝 틱**에 닿는다(몸이 늦게 모양에 들어온다): r + 1.0834 ≤ 1.5 → r ≤ **0.417**
  (가장 이른 J 0.0167 에 0.3999 를 더한 값). 테스트는 이 끝을 잰다.

**(4번 PR · #82) 게이지 쪽의 반격은 1타 하나다.** 게이지를 깬 것이 2타면 그 2타를 끝까지 휘두르고 **2타 뒤 경직(0.5초 · §5.1)까지**
서야 다음 칼이 선다 — 2타 도중 · 2타 뒤 경직 중의 J 는 잇지 않는다(2연격의 끝이다). 가장 나쁜 경우는 2타가 판정 창의 첫 틱에 닿아
무너뜨린 것이다:

```
무너짐 ─┬─ 2타의 남은 판정 + 후딜   0.3333
        ├─ 2타 뒤 경직             0.5000   (30틱)
        ├─ 다음 틱의 J             0.0167
        └─ 반격 1타가 닿기까지      0.1666   (선딜 + 판정 — 창의 끝 틱)
                                  1.0166   탈진 1.5 에 0.4834 가 남는다
```

반격 2연격은 이제 안 들어간다 — 그 1타에 2타까지 이으면 0.3333 + 0.5 + 0.0167 + 1.0834 = 1.9334초다. 0.4834 는 반응(0.2)을 넣어도
1타가 들어가는 틈이라, `BossDataTests` 는 패리 쪽과 같은 반응 여유(0.15)를 넣어 게이지 쪽의 1타를 못박는다. **#82 전에는** 게이지 쪽도
반격 2연격이 들어갔다(0.3333 + 0.0167 + 1.0834 = 1.4334 · 여유 0.0666 = 4틱) — 보고 반응할 틈이 아니라 쳐 오던 손을 그대로 이어 누를 틈이었다.

**그래서 받아친 쪽이 때려서 연 쪽보다 확실히 크다.** 패리로 연 탈진이 "받아쳤다 → 제일 센 걸 꽂는다" 의 상(반격 2연격 · 40)이고, 게이지로
연 탈진은 몰아친 뒤 한 대(1타 · 10)다. §11 의 "게이지가 패리 중심 고리를 약하게 할 수 있다" 를 누그러뜨리는 쪽이다.

반격 한 번에 10 + 30 = **40**, 보스 체력 200 이니 **다섯 번 받아치면 이긴다.** (4번 PR) 게이지로도 탈진이 열린다 —
연격 둘(80)과 반격 1타(10)면 90 이다(#82 전에는 반격 2연격까지 120). 패리만이 반격 창을 여는 길은 아니다(§11).

### 4.4 패턴 고르기 — 시도마다 다른 시드 · 시도 기록 · 고르기 인터페이스 (3번 PR)

> 유저: "학습은 보스가 미리 정해지지말고 재시도 할때마다 달라지게 하겠습니다." · "실시간은 아니고 보스전에 실패할때마다 업데이트 되면 됩니다."

**시도.** 전투 한 번이 시도 하나다. Battle 씬이 설 때마다(재시도 · 다음 단계 · 처음부터 · 디버그 단계 점프) 번호가 하나 오른다.

**시드.**

- **세션 시드** — 게임을 켤 때 Godot 쪽(`Game`)이 한 번 뽑는다(벽시계의 마이크로초를 `Det.Mix64` 로 섞는다).
  `--session-seed=N` 으로 고정할 수 있다. 벽시계는 **규칙 층에서만** 금지다(CLAUDE.md §4) — 규칙은 뽑힌 수를 받기만 한다.
  부팅 때 `[run][I] session_seed=N` 을 한 번 남긴다. `CmdArgs` 에 64비트를 그대로 읽는 자리(`CmdArgs.UInt64`)를 더한다 —
  `CmdArgs.Double` 은 2^53 넘는 비트를 잃는다. **`--session-seed` 와 데모의 `--seed` 가 둘 다 그것으로 읽는다.** 시도 시드는
  `Hash64` 의 출력이라 거의 다 2^53 을 넘고, 지금 데모는 `--seed` 를 `CmdArgs.Double` 로 읽는다(`BattleDemo.cs:21`) — 로그의 시드를
  그대로 넘겨도 다른 판이 돈다. 2^53 을 넘는 시드가 인자를 거쳐 같은 값으로 오는지 `CmdArgsTests` 가 본다.
- **시도 시드** = `Det.Hash64(세션 시드, Det.Domain.Attempt, k1: 시도 번호)`. 새 도메인은 **6 · `"attempt"` 하나**다 —
  번호는 뒤에 더할 뿐이다(CLAUDE.md §4). 고르기는 지금처럼 `PatternPick`(1)을 쓴다.
- 전투를 세울 때 `[run][I] attempt=N stage=S seed=X picker=uniform history=K` 를 남긴다(K = 그때까지의 기록 수).
  고르기가 `uniform` 인 동안은 어느 시도든 (세션 시드, 시도 번호) — 로그의 `seed=X` 를 데모에 `--seed=X --stage=S` 로 넘기면 — 보스의
  순서를 되살린다. **기록을 읽는 고르기(망)가 들어오면 그렇지 않다** — 같은 시드라도 그 시도 앞의 기록이 있어야 같은 분포가 선다.
  그때의 되살리기는 기록의 저장과 함께 망 PR 이 정한다(아래 「시도 기록」).
  `[scene][I] battle ready stage=S fighter=…` 줄은 그대로 둔다 — 스모크가 그 앞머리를 본다.
- 세션 시드와 시도 번호는 처음부터(`ResetRun`) 해도 안 돌아간다 — 그래야 한 세션 안에서 (시드, 번호)가 하나뿐이다.
- 이름이 "런" 이 아니라 "세션" 인 이유: 코드의 run(`ResetRun` · `[run][I] stage=`)은 이미 "1단계부터 클리어까지" 를 뜻하고, 이 시드는 그보다 오래 산다.
- **고정 시드 51 은 고정이 목적인 곳에만 남는다:** 헤드리스 데모(`--seed`, 기본 51 — 시도 시드 그 자체, Game 을 안 탄다),
  리플레이 골든, 테스트. 스모크와 스크린샷은 Game 을 타므로 `tools/build.sh` 가 `--session-seed=51` 을 넘긴다 —
  시도마다 시드는 여전히 다르지만 실행마다 같아 스크린샷이 같은 판을 찍는다.

**시도 기록.**

- `RunHistory` — 규칙 층의 순수 클래스(csproj 에 링크 · TDD 게이트 안). `AttemptRecord(Number, Stage, Seed, Outcome, Events)` 의 목록이다.
  `Game`(Autoload)이 하나를 든다 — 씬이 다시 서도 산다. 로직을 `Game.cs` 에 두면 테스트 밖으로 나간다.
- 전투가 끝나는 곳(`Battle.Finish` — 판마다 한 번, `_sim.Events` 가 살아 있는 마지막 자리)에서 붙인다.
  **이긴 판도 붙는다** — 1단계를 이긴 판이 곧 "1단계 기록" 이다.
- 끝까지 안 간 전투(F9 · 단계 점프 · 도중에 타이틀)는 결과가 없어 안 붙는다. 번호는 이미 올랐다.
- **처음부터 하면 기록을 비운다** — 타이틀로 가거나 클리어 뒤 [처음부터]. 새 런은 1단계에서 다시 잰다.
- **디스크에 남기지 않는다** — 게임을 끄면 사라진다. 저장은 망 PR 이 정한다(기록을 읽는 쪽이 생길 때). 그 PR 은 기록을 읽는
  고르기의 판을 되살리는 길도 같이 정한다 — (세션 시드, 시도 번호)만으로는 그 판이 안 선다(위 「시드」).

**고르기 인터페이스.**

- `IPatternPicker.Pick(int draw)` → 명부의 칸 번호. `BattleSim.Begin` 이 부르는 자리 하나다 — 지금의 `Det.RollInt(…)` 한 줄이다.
  몇 번째로 뽑는지(`draw`)는 `BattleSim` 이 센다. 고르기는 그 번호로 좌표를 조회하므로 상태가 없어도 된다.
- 고르기는 **시도를 시작할 때** 그때까지의 기록으로 한 번 세운다 — 판 도중에는 안 바뀐다. 유저의 "실시간은 아니고 실패할 때마다 업데이트" 가 이것이다.
- 등록표 (CLAUDE.md §2): `stages.json` 의 단계마다 `picker` id → 구현. 세우는 재료는 (명부, 기록, 시도 시드, 단계, **대본**)이다.
  대본(`IReadOnlyList<string>?` — 패턴 id 의 순서)은 `script` 만 읽고, 다른 구현은 모른다.

  | id | 구현 | PR |
  |---|---|---|
  | `uniform` | `Det.RollInt(시드, PatternPick, 명부 수, k1: draw)` — 지금의 `Begin` 과 **비트까지 같다** | 3 |
  | `script` | 대본의 순서를 돌고, 끝나면 처음부터 다시 돈다. 명부에 없는 id 는 세울 때 거절한다. GIF 도구와 스크린샷이 패턴을 고정하는 데 쓴다 — 데이터의 단계에는 안 쓴다 | 5 |
  | (망) | 기록을 읽어 분포를 짓고 `Det` 로 뽑는다 | 나중 |

- `uniform` 이 지금의 뽑기를 비트까지 되풀이하므로 인터페이스를 끼우는 것만으로는 순서가 안 움직인다 — 골든을 움직이는 것은 새 패턴이다.
- `BattleSetup` 의 고르기 칸은 **선택**이다 — 비우면 (`Seed`, `PatternIds`) 위의 `uniform`. 3번 PR 뒤에 남는 테스트의 `BattleSetup` 열일곱 곳이
  그대로 선다(지금 열아홉 곳 중 `VariantRhythmTests` · `WedgeSealTests` 의 두 곳은 그 파일과 같이 지워진다 — §8).
- **대본이 전투에 닿는 길** (5번 PR). `Game` 이 **다음 전투 하나에만** 쓰는 대본 칸을 든다(`SetStage` 옆). GIF 러너(§6.2)와
  `ShotRunner` 가 그 칸을 채우고 전투로 가면, `Battle` 은 그 전투의 고르기를 단계의 `picker` 대신 `script` 로 세우고 칸을 비운다 —
  로그는 `[run][I] attempt=… picker=script`. `stages.json` 은 안 건드린다: 데이터에 `picker: script` 를 적는 길을 안 만든다.
- `stages.json` 의 `picker` 는 `required` 다 — 빠지면 부팅이 빠진 키를 나열하고 멈춘다. 모르는 id 는 데이터 테스트가 막는다.
- **1단계는 망이 들어와도 `uniform` 이다.** 이 단계가 "무엇에 기대는가" 를 재는 자리라, 고르기가 기록을 읽으면 2단계가 읽을 측정이 기운다.
  재시도마다 다른 것은 시드로 이미 된다.

**망이 들어오면.** 망은 구현 하나를 등록표에 더한다. 그때 **`uniform` 이 대조군이 된다** — 같은 사람에게 무작위 보스와 망 보스를
붙여 비교하는 것 말고 망이 일하는지 증명할 길이 없다. 그런데 `stages.json` 의 `picker` 는 단계마다 id **하나**라, 그 한 줄을 바꾸면
2단계가 통째로 망이 되고 대조군이 없다. 그래서 망 PR 은 **시도마다 갈래를 정하는 자리**를 같이 더한다 — 예: 새 `Det` 도메인(번호는 뒤에 더한다)의
동전 하나로 그 시도에 망과 `uniform` 중 하나를 붙이고, `[run][I] … picker=` 가 붙은 쪽을 남긴다. 기록(`AttemptRecord`)도 갈래를 싣는다.
망이 읽는 것은 1단계 기록과 2단계 재시도 기록이다 — 유저의 "1단계 보스를 피했던 패턴, 2단계 보스를 재시도하며 피했던 패턴들".
겨냥의 뜻은 §6.2 의 표가 적는다.

### 4.5 경직 게이지 (4번 PR)

> 유저: "유저에게 공격을 당하면 경직 게이지가 차오릅니다. 이건 상단에 체력게이지 밑에 표시합니다. 경직 게이지는 시간이 지나면
> 서서히 줄어들고 공격을 받으면 차오릅니다. 경직이 꽉차면 어떤 행동을 하고있었든 … 탈진상태가 됩니다. 유저의 두번째 2타공격은
> 더 큰 경직도를 쌓도록 해주세요."

**모델.** 보스의 경직도는 0 ~ `poise_max` 다.

- 파이터의 칼이 닿으면 그 칼질의 경직도(`fighters.json` 의 `combo[].poise`)만큼 찬다. **칼질 하나에 한 번이다** — "한 번
  휘두르면 한 번만 맞는다" 와 같은 자리다. 끝에서 멈추고 넘치지 않는다.
- **마지막으로 맞은 뒤 `poise_decay_delay` 동안은 그대로**다가, 그 뒤로 틱마다 같은 양(`poise_decay_per_second` × 한 틱)이 빠진다.
  새로 맞으면 유예가 처음부터 다시 선다.
- 끝까지 차면 **탈진**이다 (§4.3). 탈진하면 비우고, 탈진 동안에는 안 찬다.
- **결정타는 안 채운다** — 이긴 판에 탈진은 뜻이 없다.
- 받아친 패리는 게이지를 안 채운다 — 받아치면 곧장 탈진한다(§4.3).
- 보스는 맞아도 하던 것을 멈추지 않는다 — 규칙에서 바뀌는 것은 체력과 게이지뿐이다. 그림은 흰 플래시뿐이다 (§6).
- 난수가 없다. 채움은 정수, 줄어듦은 늘 같은 상수라 같은 시드면 같은 결과다. 유예와 탈진은 틱으로 센다.
- 로그가 "왜" 를 틀리게 말하지 않는다: 채움 줄(`[strike][D] … poise=`)은 **실제로 찬 양**을 찍는다 — 탈진 중에 때려 안 찬 칼을 45 로 적지 않는다.

| 키 | 값 | |
|---|---|---|
| `poise_max` | 100 | 칼질마다의 값이 곧 백분율로 읽힌다 |
| `combo[0].poise` (1타) | 10 | 기본 단위 |
| `combo[1].poise` (2타) | **45** | "2타가 더 큰 경직도" — 1타의 네 배 반 |
| `poise_decay_delay` | 1.2초 (72틱) | 한 연격(1.0001초)을 0.1999 남기고 덮는다 |
| `poise_decay_per_second` | 10 | "서서히" — 가득 찬 게이지가 10초에 빠진다 |

**산수.**

- 2연격 한 번 = 10 + 45 = **55 < 100** — 안 무너진다. 연달아 두 번이면 10 → 55 → 65 → **110** — **두 번째 2타에 무너진다.**
- 유예가 연격을 덮는가: 1타가 판정 창의 첫 틱에 닿고 2타가 창의 끝 틱에 닿는 가장 긴 경우가 0.0833 + 0.0834 + 0.6667 + 0.1667 =
  1.0001초다. 1.2 − 1.0001 = 0.1999 가 남는다.
- 스태미나 하나당 경직도: 2연격 55/28 = 1.96 · 1타만 10/14 = 0.71 — 이어 치는 쪽이 쌓는다. 초당으로 견주지 않는다: 1타만
  쉬지 않고 치는 빠르기(0.667초마다 — 1타 16틱 + 1타 뒤 경직 24틱 · #82)는 스태미나가 못 버틴다 — 회복은 Idle 에서만 초당 40 이고
  경직은 Idle 이 아니다(§5.1). #82 전에는 0.267초마다(스태미나 초당 52)였다.
- 1타만 치면: 스태미나 한 통을 쉬지 않고 쏟아도 못 무너뜨린다 — 일곱 번(98)에 마지막 한 번(§5.5)을 더해 여덟 번 · 80 이고,
  그 뒤 파이터가 탈진한다. 다만 유예(1.2)가 1타 사이보다 길어 **꾸준히 찌르는 동안에는 게이지가 안 줄어든다** —
  스태미나가 버티는 빠르기(약 1.0초마다: 칼질 0.27초 + 1타 뒤 경직 0.40초 + Idle 0.35초 × 40 = 14 · #82)로 찌르면 열 번째 1타(첫 타에서
  약 9.2초)에 무너진다. #82 전에는 0.6초마다 · 5.4초였다.
- 빠지는 시간: 가득 찬 게이지 1.2 + 10 = 11.2초, 2연격 한 번 분량 1.2 + 5.5 = 6.7초.
- 판 전체: 연격 둘(80) + 반격 1타(10) = 90 / 200 (#82 — 전에는 반격 2연격 40 으로 120).

**데이터가 지킬 것**(`FighterDataTests` · `BossDataTests`): 2타 > 1타 · 2연격 한 번 < 끝 ≤ 두 번 · 스태미나당 이어 치기가 더 쌓는다 ·
유예가 한 연격을 0.15 넘게 남기고 덮는다 · 게이지를 깬 2타 뒤에도 반격 1타가 반응 여유 0.15 를 남기고 탈진 안에 든다(§4.3 · #82).

### 4.6 1타 → 돌진 → 3타 — `1타 돌진` (5번 PR)

> 유저: "멀리서 패턴을 보고 패턴이 끝난 경직 타이밍만 노려서 찔끔 공격하는 유저를 타겟으로 1타 공격까지만하고 run 애니메이션을
> 재생해서 유저에게 아주 빠르게 다가가서 3타 공격을 하는겁니다."

| 패턴 시계 (초) | 틱 | 그림 | |
|---|---|---|---|
| 0.000 ~ 1.300 | 1 ~ 77 | `attack1` f0 ~ f3 | **3연격과 같다** — ★ 1타 0.850 (51 ~ 58틱) · 피해 8 |
| 1.300 | 78 ~ A | `run` (제 속도 · 반복) | **돌진** — 닿는 틱 A 까지 **패턴 시계가 1.300 에 선다** |
| 1.300 ~ 1.550 | A + 1 ~ A + 14 | `attack3` f0 → f1 | |
| **1.550 ~ 1.675** | **A + 15 ~ A + 22** | **f2** | **★ 3타 · 피해 14** — 3연격의 3타와 같은 판정 |
| 1.675 ~ 2.150 | A + 23 ~ | f3 | 끝 |

- **패턴 시계.** 돌진 단계(T = 1.300)에 들면 시계가 그 자리에 서고, 그 뒤의 단계는 **T 가 같아도** 돌진이 끝나야 든다.
  돌진이 틱 A 에 끝나면 A + 1 부터 시계가 다시 간다 — 그래서 3타는 언제나 도착 뒤 15틱(0.25초)에 선다. 데이터의 T 는 선 시계로 적는다.
  돌진 없이 곧장 닿으면 A = 78 이라 3타가 93틱에 선다.
- **1.30초까지는 3연격과 한 틱도 안 다르다.** 멀리서 지켜보는 사람이 "3연격이구나" 하고 후딜을 기다리게 두는 것이 이 패턴의 미끼다.
- **돌진.** 매 틱 앞쪽 거리 `d = (파이터 X − 보스 X) × 보는 쪽` 을 잰다(파이터가 이번 틱을 먼저 움직인 뒤다).
  `d ≤ S` 면 그 틱에 돌진이 끝난다. 아니면 앞으로 `min(v / 60, d − S)` 간다 — 닿으면 d = S 로 끝난다. 보스는 뒤로 안 간다.
  - `speed` v = **3600 px/s** — 틱당 정확히 60px.
  - `stop` S = **280**.
- **보는 쪽은 그대로다**(패턴 중 잠금). **돌진 도중에는 파이터가 등 뒤로 못 간다** — 보스가 움직인 뒤 d ≥ 280 이고, 파이터는 한 틱에
  많아야 36.7px(대시 · 점프의 가로는 걷기와 같은 7px) 다가오므로 다음 틱의 d 는 243.3 이상이다. 그러면 d ≤ S 라 그 틱에 돌진이 끝난다 —
  **돌진은 언제나 d ∈ [243.3, 280] 에서 멈춘다**(곧장 닿은 경우는 아래).
- **d < 0 은 돌진이 시작하는 78틱에만 있다** — 1타 동안(1 ~ 77틱) 이미 보스를 뚫고 지나가 등 뒤에 있던 사람이다. 그때 돌진은 0틱이고
  3타는 앞으로 헛친다. 3타의 등 뒤 궤적은 412.5 위에만 있어(§2) 땅에 선 사람은 안 맞는다.
- **뚫고 지나가기의 답은 3타의 선딜 15틱 안에 있다**(아래 「수치의 근거」 280) — 멈춘 자리에서 안으로 대시하면 등 뒤로 빠진다.
  "뛰어넘거나 대시로 뚫고 지나가면?" 은 돌진이 아니라 그 선딜이 답한다.
- **이미 d ≤ 280 이면**(붙어 있던 사람) 돌진은 0틱이고 3타가 곧장 온다 — 3타가 3연격의 2타 박자(1.55초 · 93틱)에 떨어진다.
  겨냥 밖의 사람에게는 두 대짜리 연격(8 + 14 = 22 < 3연격 30)이다.
- 받아치면(1타든 3타든) 끊기고 탈진한다 (§4.3). 1타를 받아치면 돌진은 없다.
- 다음 판정까지 남은 시간(`NextActiveIn`)은 돌진 중에 "지금 자리에서 닿기까지 남은 틱 ⌈max(0, d − S) / 60⌉ / 60 + 0.25" 다.
  완전 정보다 — `NextActiveIn` 의 경고 그대로다(§11).
- 그림: 돌진 동안 `run` 을 **`feel.rush_anim_speed`(3) 배**로 돈다 — 10fps × 3 = 30fps, 한 장이 화면 두 프레임이다. 돌진이 0 ~ 0.433초라
  0 ~ 13장(한 바퀴 8장의 1.6바퀴)이 보인다. 제 속도(10fps)면 0 ~ 5장이라 다리가 반 바퀴도 안 돌고 미끄러지는 한 자세로 읽힌다.
  10fps 가 보스 걸음(160 px/s)에 맞는다고 치면 돌진에 맞추는 배속은 3600 / 160 = 22.5배(225fps)라 화면(60fps)보다 빠르다 —
  60fps(6배)부터는 장이 화면 프레임마다 바뀌어 다리가 번진다.
  **발은 어느 배속에서도 미끄러진다**(30fps 에서 한 장에 120px) — 그것은 받아들이고, 배속은 "달린다" 가 읽히는 만큼만 준다. 규칙은 모른다.
- 돌진은 **움직임** 하나다(§8.1): `motion: { "id": "rush", "speed": 3600, "stop": 280 }`. 도약과 달리 **패턴 시계를 세운다** —
  도착 시각이 파이터 자리에 달려 있어서다. 시계가 선 동안에도 창은 없다(§3.5 6).

**수치의 근거.**

- **3600 px/s** — 방 끝에서 끝(보스 1835 · 파이터 30 → d = 1805)을 ⌈(1805 − 280) / 60⌉ = **26틱 = 0.433초**에 온다.
  판이 설 때의 간격(960 — 파이터 480 · 보스 1440, `BattleSim.cs:102-103`)이면 ⌈680 / 60⌉ = 12틱 = 0.2초다. 다만 첫 패턴 앞의
  간격 0.8초에 보스가 160 × 0.8 = 128px 걸어 오므로, 파이터가 안 움직였다면 첫 돌진은 d ≈ 832 에서 ⌈552 / 60⌉ = 10틱이다.
  파이터 걷기 420(7px/틱)의 8.6배, 대시 2200(36.7px/틱)의 1.64배라 걷든 대시로 빼든 거리가 벌어지지 않는다. 보스 걸음 160 의 22.5배다.
  60px 가 정수라 틱마다 같은 거리를 간다.
- **280** — 3타의 땅 사거리(파이터 중심 +80 ~ +404 · §2) 안이다. 돌진은 d ∈ [243.3, 280] 에서 멈춘다(위). 3타 선딜 0.25초(15틱) 동안
  걸어서(15 × 7 = 105px) 어느 쪽으로 가도 138.3 ~ 385 로 안에 남는다 — **걸어서는 못 벗어난다.** 대시로 빼면(366.7px) 610 이상으로 벗어나고,
  안으로 뚫으면 −123.4 ~ −86.7 로 등 뒤라 안 맞는다. 3타는 3연격의 3타라 가드 · 패리도 된다. 점프로는 못 넘는다(566.5).
- 파이터가 벽(30)에 붙어도 보스는 310 에 선다 — 보스의 자리(85 ~ 1835) 안이다.

### 4.7 1타 → 잡기 — `1타 잡기` (5번 PR)

> 유저: "대시로만 피하는 상대를 위해 1타 공격 후 잡기공격을 해봅시다. 잡기 연출은 idle애니메이션 상태에서 그냥 흰색 구가 캐릭터를
> 잡도록 합니다. 잡기는 대시중에도 잡히는 공격이고 이 공격은 판정범위가 좀 길게 해주세요 대시로 벗어나거나 움직이고 있어도 잡히게,
> 가드도 패리도 안되고 점프로만 회피 가능하면 됩니다."

| 시각 (초) | 틱 | 그림 | |
|---|---|---|---|
| 0.000 ~ 1.300 | 1 ~ 77 | `attack1` f0 ~ f3 | **3연격과 같다** — ★ 1타 51 ~ 58틱 · 피해 8 |
| 1.300 ~ 1.700 | 78 ~ 101 | `idle` | 흰 구가 보스에게서 떠나 파이터에게 날아간다 (뷰) |
| **1.700 ~ 1.825** | **102 ~ 109** | `idle` | **★ 잡기 · 바닥 전체 · 높이 0 ~ 60 · 피해 25 · 1.0초 붙든다** |
| 1.825 ~ 2.700 | 110 ~ 161 | `idle` | 붙들고 선다 · 162틱에 끝 |

**판정.**

- **바닥 전체, 좌우 대칭** — `band: [0, 1920, 0, 60]` (점프 공격의 착지 띠와 같은 모양 · §4.2).
  보는 쪽으로만 길게 두면 보스 몸을 대시로 뚫고 지나가 빠진다: 서 있는 거리 115 에서 36.7px/틱이면 4틱 뒤 −31.7, 몸의 앞끝이 −1.7 로
  이미 뒤다. 유저의 "대시로 벗어나거나 움직이고 있어도 잡히게" 를 못 지킨다. 걷기(7px/틱) · 대시(366.7px)로는 바닥 전체를 못 벗어난다.
- **높이 60** — 착지 띠와 같다: 점프로 넘는 법을 한 번 배우면 둘 다 넘는다. 8틱 창을 넘는 누름은 창이 열리기 3 ~ 48틱 전(46틱 · 0.767초 — §4.2)이다.
  다만 1타 창(51 ~ 58틱) 안에서 뛰면 1타에 맞을 수 있어, 1타 뒤로 치면 59 ~ 99틱(41틱 · 0.683초)이다.
- **창 8틱**(0.125초 · 한 장) — 다른 판정과 같다. 대시 · 걷기로는 길이와 무관하게 못 벗어나므로 길게 둘 까닭이 없고,
  길게 두면 점프의 누름 창만 줄어든다(창이 N틱이면 누름은 54 − N틱).
- **1.70초에 여는 이유.** 대시로 피하는 사람은 창의 시각과 무관하게 잡힌다 — 무적을 안 받고 바닥 전체라서다. 그래서 시각은
  **점프로 답하는 사람**을 위해 고른다. 3연격 · 돌진과 갈리는 첫 그림(1.30초의 `idle` · 78틱)에서 창(102틱)까지 흰 구가 0.40초를 날고,
  누름은 창보다 3틱 앞이면 되니 보고 뛰는 몫이 102 − 3 − 78 = **21틱(0.35초)** 이다 — 사람 반응 0.2초에 0.15가 남는다.
  3연격의 2타 박자(1.55초)에 열면 그 몫이 12틱(0.2초)뿐이라 보고 뛰는 사람도 반은 잡힌다. 창은 정수 틱이다(1.70 × 60 = 102 · §3.6 ⑤).

**답 — 판정 단위로 적는다** (§7.3 · §8.1): `"dash": false, "guard": false, "parry": false, "grab_hold_seconds": 1.0`.

- 대시 무적을 안 받는다 · 가드 중이어도 맨몸이다(붕괴가 아니다) · 패리 창 안이어도 맨몸이다 · **점프로만 넘는다.**
- 닿으면 판정 결과는 **잡힘**(`Grabbed`)이다 — 새 판정 결과 하나다. 맞음과 가르는 이유: 뷰가 흰 구를 붙이고,
  로그와 계측이 "잡혔다" 를 "맞았다" 와 따로 센다. 규칙은 판정의 깃발(`grab_hold_seconds` > 0)과 결과로 가른다 — 패턴 이름으로 가르는 분기가 없다(CLAUDE.md §2).
- **잡히면:** 피해 25 · `grab_hold_seconds` 1.0초(60틱) 동안 붙들린다. 하던 행동(칼질 · 대시 · 패리 · 가드)이 그 자리에서 끝나고,
  행동 · 이동 · 점프 · 가드가 다 막힌다. 공중에서 잡혔으면 그대로 떨어진다. 스태미나는 Idle 이라 찬다(붕괴 고정 · 탈진과 같다).
  풀리면 그대로 선다.
- 규칙에서 붙들림은 탈진과 **같은 고정**을 쓰되 **다른 상태**다(`Fighter.Held`) — 뷰가 흰 구와 탈진 색을 가른다.
  그 고정은 4번 PR 이 붕괴의 고정을 파이터 탈진으로 넓힌 것(§5.5)이다 — 잡기가 4번 뒤에 오는 까닭이다(§10).
- **붙들림과 탈진이 겹치면.** 고정(`Locked`)은 하나이고 길이는 **남은 것과 새 것 중 긴 쪽**(max)이다 — 지금은 `_lockLeft` 를 새 값으로
  덮어써(`Fighter.cs:217`) 탈진이 막 든 뒤(남은 것이 60틱보다 긴 첫 6틱)에 잡히면 더 일찍 풀린다. 상태는 따로 센다: 뷰는 붙들림이 남은 동안 붙들림(흰 구 · `hit` 마지막 장)을,
  그 뒤에 탈진이 남으면 탈진 색을 그린다. 겹치는 길은 둘이다.
  - **탈진한 채 잡힌다.** 1타(51틱)에 가드가 깨져 117틱까지 탈진인 사람은 못 뛰어 102틱에 잡힌다 — 고정은 max(15, 60) = 60틱이다.
  - **잡기가 마지막 스태미나의 행동을 끊는다.** 잡기가 끊은 행동도 끝난 행동이다 — 그 행동의 값으로 0 이 됐으면(§5.5) 같은 틱에
    탈진도 든다. 고정은 max(60, 66) = 66틱, 60틱 흰 구 뒤 6틱 탈진 색이다. 창의 끝 틱(109)에 잡혀도 175틱에 풀려 다음 판정(261틱)까지 1.4초가 남는다.
- **25** — 한 대(14)보다 확실히 크고 3연격 한 바퀴(30)보다 작다. 한 번 잡히는 것이 "한 바퀴를 거의 다 먹은 것" 으로 읽힌다.
  체력 110 이면 네 번은 버티고(100) 다섯 번째에 죽는다(125).
- **1.0초** — 흰 구가 붙든 모습이 보일 만큼 길고, 붙들린 동안 다음 칼이 안 온다: 창의 마지막 틱(109)에 잡혀도 169틱 무렵 풀리고,
  패턴이 162틱에 끝나 간격 48틱 뒤 다음 패턴의 가장 이른 판정(3연격의 1타 · + 51)은 261틱이다 — 풀린 뒤 1.5초가 남는다.
- **패턴이 2.70초에 끝나는 이유**: 창이 열린 뒤 붙드는 1.0초가 지나야 보스가 다음으로 간다. 흰 구가 붙들고 있는 동안 보스가
  다음 패턴을 시작하면 그림이 거짓말이다. 안 잡힌 사람(뛴 사람)에게는 1.0초의 빈 `idle` — 정답의 상이다.
- 받아치면(1타) 끊기고 탈진한다 — 잡기는 없다.
- 관측: 잡힘의 수단은 그 순간 하던 것 중 **가장 최근에 시작한 것** — 대시 · 패리 · 점프 · **가드**. "대시했는데 잡혔다" 가
  이 패턴이 잡으려는 사람의 기록이다. 가능했던 답은 점프만 참이다(§7.3).
- 그림 (§6): 보스는 1.30초부터 `idle`. 흰 구가 보스 몸 가운데에서 떠나 창이 열리는 틱에 파이터에 닿는다. 잡았으면 붙들린 동안
  파이터를 감싸고 풀릴 때 흩어진다. 못 잡았으면(뛰었으면) 창이 닫힐 때 바닥에서 흩어진다. 규칙은 흰 구를 모른다 — 뷰가 규칙의
  단계와 잡힘 관측을 보고 그린다. 붙들린 파이터는 `hit` 를 한 번 돌고 마지막 장에 선다.

### 4.8 점프 ×3 — `점프 3연속` (5번 PR)

> 유저: "점프공격은 2단계에선 그냥 3번 재생되도록 만들어봅시다."

점프 공격(§4.2)의 1.50초를 **그대로 세 번** 잇는다. 타임라인은 점프 공격을 0 · 1.50 · 3.00초에서 세 번 적은 것이다.

| 번째 | 도약 | 착지 창 |
|---|---|---|
| 1 | 0.40초 (24틱) | 1.00 ~ 1.125 (60 ~ 67) |
| 2 | 1.90초 (114) | 2.50 ~ 2.625 (150 ~ 157) |
| 3 | 3.40초 (204) | 4.00 ~ 4.125 (240 ~ 247) |
| 끝 | 4.50초 (270) | |

- **매 도약이 그 틱의 파이터를 겨냥하고 그쪽으로 돌아선다** — §4.2 의 규칙 그대로다. 파이터가 옮겨 가도 따라간다.
- 창 사이는 90틱이다. **점프로 매번 답이 되는가**: 창 k(T_k)를 넘긴 누름 P 는 P ≤ T_k − 3 이라 P + 60 에 내리고 P + 61 부터 다시 뛴다
  → 늦어도 T_k + 58. 다음 창의 마지막 누름은 T_k + 90 − 3 = T_k + 87 이다 — 다음 창을 넘는 누름이 **T_k + 58 ~ + 87 의 30틱** 남는다. 가장 이른 누름(T_k − 48)이면
  T_k + 13 에 다시 뛸 수 있어 다음 창의 첫 누름(T_k + 42)보다 이르다. 셋을 다 점프로 넘을 수 있다.
- **가드로 매번 답이 되는가**: 12 × 1.8 = 21.6 씩 세 번 = 64.8 < 100 — 가득 찬 스태미나로 셋을 다 막는다(칩 3 × 3 = 9).
  가드 중에는 안 차므로(Idle 에서만) 이어 막을수록 준다: 100 → 78.4 → 56.8 → 35.2.
- 패리 불가 · 대시는 창이 열리는 그 틱만(§4.2). 공중에서 무너지면(4번 PR) 남은 도약은 없다.

### 4.9 엇박 3연격 — `엇박 3연격` (5번 PR)

> 유저: "2단계 공격에 패리를 많이 하던 유저를 위해 엇박으로 타이밍을 바꾸는 3타공격도 넣어봅시다"

3연격과 **같은 세 타**다 — 같은 판정 · 같은 피해(8 · 8 · 14) · 가드 · 패리 · 대시 · 간격이 다 된다. 다른 것은 박자 하나다:
**타마다 칼이 오르기 전의 장(f0)을 0.15초 더 붙든다.** 칼이 오르는 f1 에서 판정까지는 3연격과 같은 한 장(0.125초 · 7틱)이다.

|---|---|---|---|
| 0.000 ~ 0.875 | 1 ~ 52 | `attack1` f0 | **0.15 더 붙든다** (0.725 → 0.875) |
| 0.875 ~ 1.000 | 53 ~ 59 | f1 | 3연격과 같은 0.125 |
| **1.000 ~ 1.125** | **60 ~ 67** | **f2** | **★ 1타 · 8** |

**어느 타를 늦추나 — 셋 다.** 어느 타든 받아치면 연격이 끊기므로(§4.3) 한 타만 늦추면, 패리하는 사람은 앞의 제 박자 타를
받아쳐 패턴을 끝낸다 — 엇박이 올 자리가 없다. 셋 다 늦추면 박자로 누르는 사람은 첫 타부터 맞고, 맞은 뒤 다음 타를 그 타에서
3연격의 간격으로 재도 또 늦다: 1타 60틱(3연격 51 · +9), 1→2타 51틱(3연격 42 · +9), 2→3타 75틱(3연격 66 · +9).

**0.15초 = 9틱의 근거** — 틱으로 잰다(누른 틱 P 에서 Advance 가 먼저 돌아 그 틱의 경과가 1/60 이다).

- 패리 창: 경과 < 0.133 인 틱 = P ~ P + 6 (7틱). 커밋: 패리가 P ~ P + 18 까지 돌고 P + 19 에 풀린다 — 가드 · 대시는 P + 20 부터다.
  **P + 19 도 맨몸이다** — `Fighter.Tick` 은 `Begin` → `Advance` 순이라(`Fighter.cs:246`) P + 19 의 누름은 패리가 풀리기 전에 버려지고,
  그 틱에 풀린 파이터는 가드도 대시도 아닌 Idle 로 판정을 받는다.
  **(#82) 이제 P + 19 에 풀리지 않고 패리 뒤 경직(0.25초 = 15틱)에 든다** — 경직이 P + 19 ~ P + 33, P + 34 에 풀리고 가드 · 대시는 P + 35
  부터다(§5.3). 아래 산수의 맨몸 끝(P + 19)은 **P + 34** 로 늘어 `7 ≤ δ ≤ 28` 이 된다. 9틱은 그대로 서고 끝에 19틱이 남는다 — 그리고
  박자로 누른 패리가 헛치면 전보다 **0.25초 더** 묶인다. 엇박의 미끼가 그만큼 비싸다: 5번 PR 은 이 산수 위에서 잰다.
- 3연격의 박자에 맞춰 받아쳤을 누름은 판정보다 0 ~ 6틱 앞선 누름이다. 판정이 δ틱 늦으면 그 누름에서 k0 + δ 틱 뒤에 온다(k0 ∈ 0 ~ 6).
  창을 지나고(k0 + δ ≥ 7) 맨몸에 떨어지려면(k0 + δ ≤ 19) **7 ≤ δ ≤ 13** 이다.
- **9틱을 고른 이유.** 판정 시각이 정수 틱이려면(§3.6 ⑤) 늦춤이 소수로 딱 떨어지는 초여야 한다 — T × 60 이 정수인 소수는 0.05초(3틱)의
  배수뿐이라 7 ~ 13 안에서는 **9(0.15초)와 12(0.20초)** 둘이다. 9 는 박자로 누른 누름을 모두 + 9 ~ + 15 에 떨어뜨려 가장 늦게 누른 것도
  창(+ 6)을 3틱 넘고 가장 이르게 누른 것도 맨몸의 끝(+ 19)을 4틱 남긴다. 12 는 + 12 ~ + 18 이라 끝에 1틱만 남는다.
- **보고 누르는 사람은 받아친다.** 3연격이면 칼이 오르는 44틱(0.725초)에 엇박은 f0 에 그대로 서 있다 — 판정(60틱) **16틱(0.267초) 앞**에
  보이는 다름이다. 그것을 보고 반응해 누르면 반응이 10 ~ 16틱(0.167 ~ 0.267초)일 때 창(54 ~ 60)에 든다 — 반응 0.2초(12틱)면 56틱이다.
  2 · 3타도 같다: 앞 타에서 3연격의 간격으로 재면 칼이 올라야 할 틱(95 · 170)이 판정(111 · 186)보다 16틱 앞이다.
  칼이 **오르는 것**(f1 · 판정 7틱 앞)을 보고 누르는 것은 3연격에서도 엇박에서도 반응(12틱)이 모자라 늦다 — 받아치는 단서는
  "칼이 안 오른다" 쪽이다.
- **f1 이 아니라 f0 를 붙드는 이유.** f1 을 붙들면 두 패턴이 44틱에 똑같이 칼을 올리고 51틱(3연격의 판정 박자)에야 갈린다 — 판정 9틱(0.15초) 앞이라
  반응 0.2초로는 누구도 창(54 ~ 60)에 못 닿는다. 그러면 1타는 박자로 누르는 사람과 보고 누르는 사람을 못 가르고, 미리 든 가드나 찍기만 남는다.
- 한 장(0.125초 = 7.5틱)을 붙들면 판정이 반 틱에 떨어져 반올림이 타마다 7 · 8틱으로 흔들리고 창이 다음 장 뒤까지 산다(§3.6 ⑤).
  0.15초면 세 판정이 다 정수 틱이다(60 · 111 · 186). 붙든 f0 의 끝(0.875 · 1.725 · 2.975 — 52.5 · 103.5 · 178.5틱)은 반 틱이지만
  그림 장의 경계라 된다(§3.6 ⑤) — 반올림으로 53 · 104 · 179틱에 f1 이 든다. 뷰가 장을 규칙대로 붙드므로 한 장의 길이에 매이지 않는다.
- 0.725초까지 3연격과 같으므로 둘은 칼이 올라야 할 장에서 갈린다 — 그것이 엇박이다.

타 H 를 받아치려면 누름이 H − 6 ~ H(판정 앞 0.117초 · 창 7틱) 안이어야 하고, 헛친 누름 P 뒤로는 P + 35 부터 누를 수 있다.

- **1타 → 2타 (42틱 · 0.70초).** 2타(93)의 창은 87 ~ 93 이다. 1타를 **일찍** 헛친 누름(P ≤ 44 — 1타 앞에서 창이 닫혔다)은 늦어도 79 에
  풀려 2타의 창이 열리기 8틱 앞이다 — 창을 온전히 쓴다. 1타를 **늦게** 헛친 누름(1타를 맞고 누른 것 · P ≥ 52)은 P + 35 ≤ 93, 곧
  **P ≤ 58**(1타 뒤 0.117초 안)이어야 2타 전에 풀린다. 0.70 − 0.583 = 0.117 이 그 여유다. #82 전에는 P ≤ 73(0.367초)이었다.
- **2타 → 3타 (66틱 · 1.10초).** 3타(159)의 창은 153 ~ 159 다. 2타를 일찍 헛친 누름(P ≤ 86)은 늦어도 121 에 풀린다(창 32틱 앞).
  늦게 헛친 누름도 P ≤ 124(2타 뒤 0.517초)면 된다.
- 그래서 **보고 누르다 한 번 헛친 사람은 다음 타에 다시 선다.** 늦게 헛친 1타만 좁아졌다 — 1타를 맞고 나서 0.117초 넘게 늦게 누른
  패리는 2타를 못 받는다.
- 5번 PR 의 엇박 3연격(§4.9)이 노리는 "박자로 누른 패리" 는 헛치면 0.25초를 더 치른다.
- **패리를 못 받는 판정이 있다** — 점프 공격의 착지 · 잡기. 창 안이어도 맨몸이다.
- 스태미나 15 (v0.6.0 `parry_cost` 그대로).
- **연타 징벌은 걷는다.** 창 0.133 / 커밋 0.333 이라 누를 때마다 60% 는 무방비로 서 있다 —
  연타는 이미 스스로 벌을 받는다. `parry_memory_window` · `parry_spam_window` 를 지운다.

- (4번 PR) 봇은 스태미나가 **값보다 많을 때만** 누른다 — 규칙이 허락하는 마지막 한 번(§5.5)도, 값이 딱 맞아 0 에 닿는 한 번도 안 쓴다. 스스로 탈진하지 않는다(#71 · 4번 PR 계획 결정 10).

### 5.5 탈진 — 스태미나를 다 쓰면 (4번 PR)

> 유저: "아 유저도 스테미나 다쓰면 탈진해야합니다."

보스와 **같은 말, 같은 생각**이다. 스태미나가 바닥나면 파이터도 탈진한다.

- **마지막 한 번은 할 수 있다(소울라이크).** 1타 · 2타 잇기 · 되받아치기 · 대시 · 패리는 스태미나가 **0 보다 많으면** 값보다
  모자라도 시작하고, 값은 0 에서 멈춘다. 전에는 값이 모자라면 안 나가서 행동으로는 0 에 닿지 않았다(100 − 14 × 7 = 2).
  가드를 드는 것은 여전히 공짜고, 공중 대시 한 번 규칙도 그대로다.
- **0 에 닿는 길은 둘이다.**
  - 행동의 값으로 0 이 되면 그 행동은 **끝까지 한다**(마지막 칼은 들어간다) — 그 행동이 **끝나는 틱**에 탈진한다. 0 에서는 2타를 잇지 않는다.
    (#82) 끝나는 틱은 **행동 뒤 경직까지 끝나는 틱**이다 — 경직 동안은 아직 그 행동이라 탈진이 안 들고 스태미나도 0 그대로다.
  - 가드로 막다가 딱 0 이 되면 **곧장** 탈진한다. 값이 남은 것보다 크면 지금처럼 가드 붕괴(전액)이고, 붕괴도 탈진이다.
- **탈진 동안**(`exhaust_seconds` 1.1초 — 옛 `guard_break_lock`, 값 그대로) 행동 · 이동 · 점프 · 가드가 전부 막힌다. 맞으면 그대로
  맞는다. 스태미나는 Idle 이라 지금처럼 찬다(1.1초에 44). 틱으로 센다 — 66틱 동안 정확히 아무것도 못 한다.
- **1.1초의 근거가 바뀐다.** 전에는 옛 변종들의 미끼 간격(1.10 · 이슈 #54)이었다 — 그 변종이 사라진다. 이제 근거는 **3연격의
  2타 → 3타 간격**이다: 93틱 → 159틱 = 66틱 = 1.1초. 2타에 깨진 가드는 3타가 서는 틱까지 못 선다 — "남은 타격을 그대로 맞는 값"
  이라는 뜻이 새 패턴 위에서 그대로 선다.
- **그림.** take-hit 를 제 속도로 한 번 돌고 마지막 장에서 멈춘다. 지금의 붕괴 색(푸른 쪽으로 식은 색)을 쓰고, 탈진 동안 스태미나
  바의 모양이 바뀐다(§6).
- 2번 PR 의 결정 4 ("1타가 끝나는 틱에 스태미나가 모자라면 잇지 않고 선다")는 이것으로 바뀌었다 — 0 에서만 잇지 않는다.

### 5.6 대시 — 뒤 경직 (#82)

> 유저: "대시 후 경직 살짝"

- 대시(0.18초 · 무적 0.14초 · 사거리 그대로)가 끝난 뒤 **`dash_recover` 0.10초(6틱)** 동안 아무것도 못 한다 — 행동 · 이동 · 점프 · 가드가
  막히고 스태미나도 안 찬다. 맞아도 안 끊긴다. **제자리다**: 대시의 이동은 대시가 끝날 때 끝나 사거리가 안 는다.
- 경직은 **대시 행동의 일부**다 — 규칙의 행동은 끝까지 `Dash` 다(§12). 그래서 그 사이 맞은 판정은 **대시의 것**이다(`DodgeCredit` —
  서 있기로 한 것이 아니라 못 움직이는 것이다). 무적은 이미 끝나 있다.
- 탈진(§5.5)은 경직까지 끝나는 틱에 든다.
- 박자: 경직이 끝나는 틱에 걸음 · 점프가 풀리고 다음 틱에 행동이 선다 — 경직이 없던 때 대시가 끝나는 틱과 같은 박자에서 정확히 6틱
  늦다(`FighterStiffTests`).
- 그림: 대시의 **마지막 자세**를 붙든다 — 빌려 쓰는 `run` 을 그 장에 멈추고 꼬리 색(무적이 끝난 대시의 어두운 색)을 그대로 둔다. `idle` 로
  두면 키가 안 먹는데 풀린 것처럼 보이고, 흘려 두면 제자리에서 달린다.

### 6.1 디버그 — 판정 보기

> 유저: "히트박스들 볼수있는 디버깅 커맨드도 만들어두세요"
> 유저: "고도에 히트박스와 판정 그런 기능들이 다 있을텐데요? 따로 보여주는 옵션도 있을겁니다"

**보여주기는 Godot 의 기능을 쓴다 — Visible Collision Shapes.** 따로 그리는 오버레이는 만들지 않는다.

| | |
|---|---|
| 켜기 | 에디터 **Debug → Visible Collision Shapes**, 또는 `HITBOXES=1 tools/build.sh run` (엔진 인자 `--debug-collisions`) |
| 끄기 | 실행 중에는 못 켜고 끈다 — `SceneTree.debug_collisions_hint` 문서가 "실행 중에 바꾸도록 설계되지 않았다" 고 한다. 시작할 때 정한다 |
| 보이는 것 | 보스 판정(이 틱에 규칙이 대 본 것) · 선딜 중 **다음** 판정이 칠 자리 · 파이터 칼 · 두 몸통. 파이터 몸통 색이 무적 · 패리 창 · 가드일 때 바뀐다 |
| 스크린샷 | `HITBOXES=1 tools/build.sh shots` — 판정이 그려진 사진은 `out/shots/` 에만 남고 `docs/shots/` 로 안 넘어간다 |

**판정은 Godot 물리로 옮기지 않는다.** 학습 데이터는 봇이 **Godot 없이** 헤드리스로 수백만 판을 돌려 만든다.
판정이 `Area2D` 에 있으면 판마다 엔진을 띄워야 하고, "같은 시드면 같은 결과"(리플레이 골든)도 물리 스텝에 묶인다.
`CLAUDE.md` §1 의 "규칙은 Godot 을 모른다" 를 컴파일러가 막는 이유가 이것이다.

그래서 이렇게 잇는다: 규칙이 판정 사각형을 계산하고, 뷰(`HitboxDebug`)는 **매 프레임 그 사각형을
`CollisionShape2D` 로 옮겨 놓기만** 한다. 충돌 계산을 하나도 안 하는 노드(Area2D · monitoring 끔 · 레이어 0)라
Godot 의 디버그 표시가 그것을 그려 줄 뿐이다.

**규칙이 실제로 대 본 사각형을 그린다 — 뷰가 다시 계산하지 않는다.** 뷰가 `hitboxes.json` 을 따로 읽어 좌우를
뒤집고 발 위치를 더하면, 규칙 쪽 그 계산에 버그가 있어도 표시는 멀쩡해 보인다 — 가장 필요한 순간에 거짓말하는
도구가 된다. 규칙은 **이 틱에 댄 (모양, 놓은 자리)** 를 기록만 해 두고(할당 없음 · 봇은 안 읽는다),
표시가 물을 때 사각형으로 편다.

- 켜고 띄웠을 때만 노드를 세운다 — 안 켰으면 사각형을 옮기는 비용도 없다.
- 켜졌을 때 `[debug][D] hitboxes=on` 을 남긴다.
- 좌우 대칭 띠(바닥 띠 포함)도 **사각형 두 장**(앞 · 뒤)으로 같은 통로를 탄다.
- (3번 PR) 파이터 몸통 색은 이 틱에 산 보스 판정에 대한 **실효** 상태를 규칙이 내놓은 대로 칠한다 — 3번은 패턴 태그(`dash_window` ·
  `parryable`)로, 5번부터는 판정 단위의 답(§7.3)으로 같은 자리를 채운다. 산 판정이 없으면 파이터 쪽 상태(무적 · 패리 창 · 가드) 그대로다.
  3번에서 이미 필요하다 — 점프 공격의 착지(`parryable: false` · §4.2) 앞에서 "패리 창" 색이 거짓말하고, 5번의 잡기 앞에서는 "무적" · "가드"
  색이 거짓말한다(#59 의 1/4 넘김이 이것을 3번에 두었다).

### 6.2 README 의 패턴별 GIF (5번 PR)

> 유저: "리드미에는 이런 내용을 각 패턴별로 1단계에서 어떤걸 많이 했고 이런 패턴이 나와서 당하는 모습을 gif로 찍어서 올리고 싶습니다."

README 에 **2단계 패턴마다 한 칸**을 둔다: "1단계에서 이것을 많이 한 사람" → 오는 패턴 → 그 사람이 당하는 GIF.

| 1단계에서 많이 한 것 (계측) | 오는 패턴 | GIF 에서 당하는 모습 |
|---|---|---|
| 멀리 서서 지켜보다 후딜에만 찔끔 친다 (`DistanceBias` 큼 · 수단이 `Spacing`) | 1타 → 돌진 → 3타 (§4.6) | 1타가 멀리서 헛치고, 후딜을 기다리던 사람에게 보스가 달려와 3타를 꽂는다 |
| 대시로만 피한다 (관측의 수단이 거의 `Dash`) | 1타 → 잡기 (§4.7) | 1타를 대시로 흘리고, 잡기 창이 열리기 0 ~ 7틱 앞(95 ~ 102틱)에 또 대시해 **무적인 채로** 흰 구에 붙들린다 — 무적 8틱(누른 틱 ~ + 7)이 102틱을 덮어야 "무적을 안 받는다" 가 찍힌다(93틱에 누르면 무적이 100틱에 끝나 무적을 받는 판정에도 잡힌다) |
| 패리를 많이 한다 (`ParryReliance` 큼) | 엇박 3연격 (§4.9) | 3연격의 박자에 K 를 누른 사람이 커밋 안에서 늦은 1타에 맞는다 |
| 가드로 버틴다 (`GuardSamples` 많음) | 점프 ×3 (§4.8) | ↓ 를 놓지 않는 사람이 3연격을 막고(54) 곧장 온 점프 ×3 의 셋째 착지에서 붕괴한다 — 54 + 21.6 × 2 = 97.2 라 셋째 21.6 을 못 낸다. GIF 는 점프 ×3 의 둘째 도약부터 잡는다 — 3연격은 잡지 않고 돈다(스태미나 바가 이미 줄어 있다) |

- **고르기는 아직 무작위다.** README 는 이 겨냥이 **설계 의도**이고, 망이 들어오면 이 표대로 고른다고 적는다 — 지금 GIF 는
  "그 패턴이 왔을 때 그 사람이 어떻게 되는가" 를 보여 준다.
- 3연격은 겨냥이 없는 바탕이라 칸이 없다.

**도구 — `tools/build.sh gifs`.**

- 대본 하나가 GIF 하나다. 대본은 **패턴을 고정하고**(`script` 고르기 · §4.4) **그 사람처럼 움직이는 파이터**를 두고 **잡을 구간**을 갖는다 —
  단계 · 패턴 순서 · (틱, 입력) 목록 · 잡을 구간 [시작 틱, 끝 틱). 틱은 **그 대본이 겨냥한 패턴의 틱**(§4 의 표와 같은 자 · 첫 틱 1)이고,
  패턴 앞의 입력(점프 ×3 칸이 처음부터 ↓ 를 붙드는 것)은 "판이 설 때부터" 로 적는다. 패턴이 고정이고 세션 시드도 고정이라 틱이 곧 박자다.
- **러너 — `GifRunner`.** `ShotRunner` 와 같은 자리(`battle/debug/` · Godot 쪽)이고 `--gif=<대본 id>` 로 뜬다. 대본은 그 안의 C# 표다 —
  스크린샷 대본이 코드인 것과 같다. 대본 id 는 ASCII 소문자(`rush` · `grab` · `offbeat` · `jump3`)다 — 인자와 파일 이름으로 쓰인다.
  러너는 `Game` 의 대본 칸과 단계를 채우고 전투로 가서(§4.4 「대본이 전투에 닿는 길」) **규칙의 틱을 보고**(겨냥한 패턴이 선 틱에서 센다)
  그 틱에 액션을 합성해 넣는다 — 벽시계로 기다리지 않는다.
- Godot 을 창으로 띄운다(`tools/build.sh shots` 와 같다 — 헤드리스는 뷰포트에 그린 것이 없다). 프레임은 **Godot 의 Movie Maker**
  (`--write-movie <폴더>/f.png --fixed-fps 60`)로 받는다 — 엔진이 모든 프레임을 고정 간격으로 쓰므로 빠지는 장이 없고 같은 대본이면 같은 장이다.
- **잡을 구간만 GIF 가 된다.** Movie Maker 는 띄운 순간부터 다 쓰고, 판은 파이터 480 · 보스 1440 에서 서서(`BattleSim.cs:102-103`)
  첫 패턴 전에 걸어 들어온다 — 그 앞머리와 앞 패턴(점프 ×3 칸의 3연격)은 돌되 안 잡는다. 러너가 구간의 첫 틱과 끝 틱에 그 순간의
  Movie Maker 장 번호를 로그로 남기고(`[gif][I] capture from=… to=…`), 끝 틱에서 끝낸다. 도구는 그 사이의 장만 ffmpeg 에 넘긴다.
- `ffmpeg`(`/opt/homebrew/bin/ffmpeg`)가 조립한다: 15fps 로 솎고 · 가로 **480px**(1920 의 1/4) · 팔레트를 떠서(`palettegen` → `paletteuse`,
  바뀐 사각형만 싣는다) `docs/gifs/<대본 id>.gif` 로 쓴다. 없으면 도구가 먼저 멈추고 설치 법을 적는다.
- **예산: 잡은 구간 4초 이하(15fps 로 60장) · 1MB 이하.** 넘으면 도구가 실패한다 — README 가 무거워지는 것을 조용히 두지 않는다.
  넷의 구간(패턴의 틱 · 맞은 뒤를 0.3 ~ 0.5초 더 보여 준다)은 다 4초 안이다.
  - 돌진(`rush`): 1 ~ 3타가 서는 틱 + 30. 3타는 A + 15 이고 A ≤ 78 + 26 = 104 라 많아야 149틱 · 2.5초.
  - 잡기(`grab`): 1 ~ 풀리는 틱(162) + 18(흰 구가 흩어지는 0.3초) = 180틱 · 3.0초.
  - 엇박(`offbeat`): 1 ~ 늦은 1타(60) + 30 = 90틱 · 1.5초.
  - 점프 ×3(`jump3`): 둘째 도약(114) ~ 셋째 착지(240) + 30 = 270틱 — 156틱 · 2.6초. 패턴 전체(4.5초)나 앞의 3연격까지(3.25 + 0.8 + 4.0 = 8.05초 넘게)는
    예산 밖이라 잡지 않는다.
- `docs/shots/` 처럼 **커밋한다** — 우리가 찍은 기록이지 에셋 원본이 아니다. `overfit/` 에 PNG 0 장 규칙은 그대로다.
- 판정 보기와 섞지 않는다 — `HITBOXES=1` 이면 도구가 거절한다.

## 7. 계측

**10축 계약은 그대로다.** 바뀌는 것은 관측이 **어느 틱을 말하는가**(§3.6 ①)와 **"고를 수 있었나" 의 출처**(§7.3)뿐이다.
끊긴 창은 관측이 없다(§3.5 5) — 축에 안 들어간다.

### 7.1 빗나간 이유

판정이 모양이 되면서 다시 가른다. **창이 열린 틱**에서(§3.6 ①), 상대 몸통을 **판정 모양 전체의 외곽 상자**와 견준다.

| 결과 | 조건 | 기록되는 수단 |
|---|---|---|
| `MissedTooFar` | 몸이 외곽 상자의 **가로 범위 밖** — 보스 등 뒤라도 모양의 뒤끝 밖이면 여기다 | 간격 (그 거리를 만든 것이 대시면 대시 — #46 규칙 그대로) |
| `MissedByHeight` | 가로로는 안인데 **외곽 상자 위**(또는 아래) | 점프 |
| **`MissedByGap`** (신규) | 외곽 상자 **안인데 빈 칸** — 초승달 안쪽 같은 곳. 단 몸 높이 궤적의 앞끝 너머나 등 뒤 뒤끝 너머는 `MissedTooFar` 다(§3.6 ②) | 간격 |

`MissedTooClose`(#46 의 안쪽 주머니)는 **`MissedByGap` 으로 흡수된다.** "보스 발밑이 비어 있다" 는 이제
"모양에 빈 곳이 있다" 의 한 경우다. `DistanceBias` 는 틈을 음수로 싣는다 — 3타에 80px 안으로 붙어 피한 사람은 "안쪽" 으로 읽힌다.

### 7.3 판정 단위의 "고를 수 있었나" (3번 · 5번 PR)

`DashAvailable` · `JumpAvailable` · `ParryAvailable` · `GuardAvailable` 은 의존도 축의 분모다 — "고를 수 있었는데 그걸 골랐나".
패턴 태그에서 가져오면 한 패턴 안에서 판정마다 답이 다를 때 거짓을 싣는다.

- **`JumpAvailable` (3번 PR) — 판정 모양에서.** "점프 한 번으로 창 내내 발이 모양 위에 있을 수 있나" = 발이 모양 윗끝 위에 있는
  틱 수 ≥ 창의 틱 수. 발 높이는 파이터 표로 이산 점프를 돌려 잰다(§4.2 의 산수). 3연격에서 1타만 참이고(27틱 ≥ 8) 2 · 3타는 거짓이다
  (윗끝이 정점 300 위다) — 태그 `jumpable` 을 그대로 실으면 2 · 3타가 "점프도 됐다" 로 실려 점프 의존도의 분모가 부푼다.
  태그 `jumpable` 은 패턴의 요약(망의 입력)으로 남고, 데이터 테스트가 "판정 하나라도 넘을 수 있다" 와 맞춘다.
- **대시 · 가드 · 패리 (5번 PR) — 판정의 답.** 단계에 `"dash": false` · `"guard": false` · `"parry": false` 를 적으면 패턴 태그를 좁힌다.
  규칙(`HitResolver`)과 관측이 같은 값을 읽는다. 잡기: 대시 · 가드 · 패리 거짓, 점프 참.
- **잡힘(`Grabbed`)은 실패다** — 맞음과 같이 아무 축도 성공으로 안 센다. 수단은 §4.7 대로(가드 포함 가장 최근의 시도).
  잡기는 점프만 가능해 점프 의존도의 분모("다른 수단도 가능했던 자리")에 안 든다 — 고를 수 없던 것을 "골랐다" 로 세지 않는다.

### 8.1 타임라인 한 단계

```jsonc
"점프 공격": {
  "tags": { "dash_window": 0.20, "jumpable": true, "parryable": false, ... },
  "timeline": [
    { "t": 0.00,  "kind": "windup",  "anim": "jump",    "frame": 0 },
    { "t": 0.40,  "kind": "windup",  "anim": "jump",    "frame": 1,
      "motion": { "id": "leap", "height": 280, "air": 0.60 } },
    { "t": 0.75,  "kind": "windup",  "anim": "attack3", "frame": 0 },
    { "t": 0.875, "kind": "windup",  "anim": "attack3", "frame": 1 },
    { "t": 1.00,  "kind": "active",  "anim": "attack3", "frame": 2,
      "band": [0, 1920, 0, 60], "damage": 12, "active_seconds": 0.125 },
    { "t": 1.125, "kind": "recover", "anim": "attack3", "frame": 3 },
    { "t": 1.50,  "kind": "end" }
  ]
}
```

- `kind` 는 windup · active · recover · end 넷이다 — `feint` 가 빠진다.
- `anim` · `frame` 은 **뷰만** 읽는다. `frame` 이 없으면 그 애니메이션을 돈다(`run` · `idle`) — 제 속도이고, 돌진의 `run` 만 `feel.rush_anim_speed` 배다(§4.6).
- 판정 단계는 `hitbox`(그림에서 뽑은 id — §3.3) **또는** `band`(바닥 띠 — §3.3) 중 **꼭 하나**를 갖는다. 모양은 판을 세울 때 한 번 찾고,
  빠진 id 는 전부 모아 한 번에 거절한다(`BattleSim.Swords` 와 같은 규약). 디버그 표시의 "다음 판정" 도 같은 함수로 짓는다.
- `motion` 은 판정이 아닌 단계에만 단다. **움직임은 id → 구현 등록표**다(CLAUDE.md §2): `leap`(3번 PR — 시각이 정해진 포물선) ·
  `rush`(5번 PR — 닿을 때까지 패턴 시계를 세운다 · 그 뒤의 단계는 T 가 같아도 기다린다 · §4.6). 하나 더할 때 러너를 안 연다.
- **움직임의 자리** (3번 PR 이 세운다). 둘 다 파이터의 X 가 있어야 한다 — 도약은 뛰는 틱에 착지 자리를, 돌진은 매 틱 d 를 잰다.
  그런데 러너는 플레이어를 모른다(`PatternRunner.cs:7`). 그래서 이렇게 잇는다:
  - `IBossMotion.Tick(MotionContext) → MotionStep`. `MotionContext` = 보스 X · Y · 보는 쪽 · **파이터 X** · 움직임이 시작된 뒤의 틱.
    `MotionStep` = 보스 X · Y · 보는 쪽 · 끝났나 · **`HoldClock`**(이 틱에 패턴 시계를 세우나).
  - 파이터 X 는 `BattleSim` 이 넣는다 — 파이터가 이번 틱을 먼저 움직인 뒤의 값이다(§4.6). 러너는 **`HoldClock` 하나만** 따른다 —
    참인 틱에 시계를 안 밀 뿐이고, 여전히 플레이어를 모른다.
  - 움직임은 단 단계에 들 때 시작해 스스로 끝났다고 말할 때까지 돈다 — 도약은 `air` 뒤(다음 단계들을 건너 착지까지), 돌진은 닿을 때.
  - `leap` 은 첫 틱에 파이터 X 로 착지 자리를 정하고 돌아선 뒤(§4.2) 식을 따라가며 `HoldClock` 은 늘 거짓이다. `rush` 는 매 틱 d 를 재고
    닿을 때까지 `HoldClock` 이 참이다.
  - 러너가 `HoldClock` 을 따르는 자리는 **3번에 둔다** — 5번이 러너를 안 열게. 3번은 쓰는 움직임이 없으니 가짜 움직임 하나로 테스트한다.
- (5번 PR) 판정의 답 `dash` · `guard` · `parry`(없으면 태그대로) · 붙드는 시간 `grab_hold_seconds`(없으면 붙들지 않는다).
- 데이터 테스트가 지킬 것: 판정 단계의 시각은 정수 틱 · 다음 단계는 창이 닫힌 뒤(§3.6 ⑤) · 움직임은 창과 안 겹친다(§3.5 6) ·
  도약 시각 + `air` = 착지 판정 시각 · `anim` · `frame` 이 보스 팩에 있다(§6) · 명부의 id 와 `picker` id 가 있다.
