# 보스전 재설계 — 1단계 두 패턴 · 그림에서 뽑은 판정 · 다크소울식 가드와 패리

**상태:** 설계 승인 (2026-09-24) · 스펙 검토 대기 · 우산 이슈 #59
**앞선 설계를 대체한다:** `2026-09-24-내려찍기-단일계열-design.md` 의 변종 아홉 · 통합 방어 · 차지.
그 문서는 기록으로 남기되, 이 문서와 어긋나는 곳은 이 문서가 이긴다.

## 0. 왜 다시 짜나

v0.6.0 을 직접 해본 유저의 결정이다. 줄이면 셋이다.

1. **링 연출이 별로다.** 공격이 동그라미로만 말한다. 보스 모션이 예고여야 한다.
2. **판정이 그림과 따로 논다.** 지금 판정은 "보스 중심에서 거리 몇~몇, 높이 몇~몇" 인 좌우 대칭 띠인데,
   그림의 칼은 앞으로 휘두르고 어떤 궤적은 등 뒤까지 감는다. **보이는 것이 곧 맞는 것**이어야 한다.
3. **범위를 줄인다.** 1단계, 패턴 둘을 먼저 완성한다. 2·3단계는 나중에.

### 성공의 기준

- 보스의 칼 궤적이 보이는 자리에 서 있으면 맞고, 안 보이는 자리(초승달 안쪽 포함)에 있으면 안 맞는다.
- 1단계 보스전이 링 없이 모션만으로 읽힌다.
- 가드(↓)와 패리(K)가 다른 선택이다 — 가드는 싸고 안전하고, 패리는 틀리면 맞지만 맞히면 반격 창이 열린다.
- 1단계를 이기면 클리어다.
- 사람과 봇이 같은 입력 통로로 이 전부를 낼 수 있다.

## 1. 유저가 말한 것 · 대화로 정한 것 · 가정한 것

### 유저가 말한 것

| | |
|---|---|
| 범위 | 1단계만, 패턴 둘. 2·3단계는 나중에. 링 연출은 걷는다 |
| 패턴 A — 3연격 | 보스 `attack1 → 2 → 3` 을 이어서. 판정 시각은 v0.6.0 1단계 그대로. 가드 불가 없는 평범한 3타. **어느 타에서든 패리 가능** |
| 패턴 B — 점프 공격 | 뛰어올라 공중에서 `attack3`, 3번째 프레임이 착지에 맞는다. 착지하면 **바닥 전체**, 높이는 **플레이어 하단 절반**. 가드 · 점프로 피한다. **패리 불가** |
| 판정 | **칼의 흰 궤적 모양 그대로.** "어택1의 3번째 프레임은 휘두른 흰색영역만큼 다 공격판정" |
| 플레이어 공격 | 차지 폐기 → `attack1 → attack2` 2연격. 2타는 **피해 3배 · 아주 느리게**. 판정은 역시 흰 궤적. **공격 중 가드 전환 불가** |
| 가드 | **아래 화살표.** 피해 감소 · 못 움직임 |
| 패리 | **K.** `attack2` 를 4프레임까지 재생하며 받아친다 |
| 패리 성공 | 보스가 `hit` 모션(흰 실루엣 아님) + 지금처럼 푸른 경직 |

### 대화로 정한 것

- 패리에 성공하면 **보스 연격이 그 자리에서 끊긴다.**
- 패리에 실패하면 **그냥 맞는다.**
- 점프 공격은 **플레이어를 향해** 뛰어든다.
- 판정 모양은 **흰 픽셀을 격자로 떠서** 저장한다 (§3).

### 가정한 것 — 틀리면 여기를 고친다

- 가드에 `↓` 와 함께 **`S`** 도 건다. 이동에 `A`·`D` 가 있어 짝을 맞춘다.
- 가드는 **땅에서만** 된다. 공중 가드는 없앤다.
- 공격 · 패리는 **끝까지 커밋**한다. 그동안 가드 · 패리 · 대시 · 이동이 전부 안 된다.
  가드는 커밋이 아니다 — 가드 중에 공격 · 패리 · 대시로 바로 넘어갈 수 있다.
- 패리 성공 시 **짧은 히트스톱은 남긴다.** 연격이 끊기므로 박자를 밀 일이 없다.
- 점프 공격에 **대시 무적도 통한다.** 무적은 모든 판정에 공통이라 막으려면 별도 규칙이 필요한데 막을 이유가 없다.
- 가드 수치(칩 25% · 스태미나 1.8배 · 붕괴 1.1초)는 **v0.6.0 그대로.**

## 2. 그림에서 확인한 것

| 시트 | 프레임 | 한 장 | 궤적이 있는 장 |
|---|---|---|---|
| 보스 `attack1` · `2` · `3` | 각 4장 · 160×111 | 8fps = 0.125초 | **f2** (세 번째) |
| 보스 `jump` · `fall` | 각 2장 | | — |
| 플레이어 `attack1` · `2` | 각 6장 · 200×200 | 12fps = 0.0833초 | **f4** (다섯 번째) |

궤적의 실제 크기 (월드 px · 보스 배율 5.5 · 플레이어 2.5 · 가로는 보는 쪽이 +):

| 판정 | 앞 | 뒤 | 높이 | 바운딩박스 대비 실제 궤적 |
|---|---|---|---|---|
| 보스 `attack1` f2 | +390 | −110 | 50 ~ 236 | 54% |
| 보스 `attack2` f2 | +434 | **−352** | 6 ~ 336 | 36% |
| 보스 `attack3` f2 | +407 | −302 | 0 ~ **566** | **29%** |
| 플레이어 `attack1` f4 | +222 | −45 | 10 ~ 172 | 42% |
| 플레이어 `attack2` f4 | +235 | −38 | 15 ~ 132 | 43% |

여기서 나오는 것 셋.

1. **사거리가 길어진다.** v0.6.0 내려찍기는 250~270px 였는데 그림의 궤적은 400px 을 넘는다.
   간격으로 3연격을 피하려면 460px 쯤 떨어져야 한다.
2. **`attack2`·`attack3` 은 등 뒤도 친다.** 보스 뒤로 돌아가는 것은 답이 아니다.
3. **`attack1` 은 점프 정점에서 넘어간다** (궤적 윗끝 236 < 정점의 몸 300~420). `attack3` 은 566 까지 올라와 못 넘는다.
   #48 에서 표본 0 이 된 **점프 축 둘이 다시 산다.**

`attack2` 의 f0~f3 은 칼을 사선으로 세운 자세라 패리 모션으로 그대로 쓴다.

## 3. 판정 모양 — 그림에서 뽑아 JSON 으로

### 3.1 왜 격자인가

| 방법 | | |
|---|---|---|
| **흰 픽셀 격자 (채택)** | 초승달 안쪽의 빈 곳이 비어 있다 | 칸 크기를 골라야 한다 |
| 사각형 3~5개 근사 | 데이터가 작다 | 초승달의 빈 곳을 일부 메운다 |
| 바운딩 박스 하나 | 가장 단순하다 | `attack3` 은 상자의 71% 가 빈 공간이다 — 초승달 한가운데 서 있어도 맞는다. **유저의 말과 정반대라 뺀다** |

### 3.2 도구 — `tools/extract_hitboxes.py`

- 입력: 설치된 에셋 `overfit/assets/<팩>/<애니>.png` (저장소에 없다 — `tools/install_assets.py` 를 먼저 돌린다).
- 판정 프레임 하나에서 **흰 픽셀**(불투명도 > 200, R·G·B 가 전부 > 235)을 모은다.
- **4×4 원본 픽셀을 한 칸**으로 떠서, 칸 안 흰 픽셀이 25% 이상이면 그 칸을 판정으로 친다.
  보스 배율 5.5 에서 한 칸은 월드 22px, 플레이어 2.5 에서 10px 이다 — 플레이어 몸통(60×120)보다 충분히 잘다.
- 같은 줄에서 이어진 칸은 **가로로 합쳐** 사각형 하나로 만든다. 데이터가 작아지고 로그로 읽힌다.
- **배율은 `balance.json` 의 `feel.*_sprite_scale` 에서 읽는다.** 뷰가 그리는 크기와 판정 크기가 따로 놀지 않게 하기 위해서다.
  어느 팩이 보스이고 파이터인지는 `bosses.json` · `fighters.json` 의 `sprite` 가 말한다.
- **기준점은 `.tres` 의 `region` 이다** — 원본 프레임이 아니다. `install_assets.py` 가 팩 전체의 불투명 범위로
  세로를 잘라 두었고(보스 2..105 · 플레이어 53..122) 뷰는 그 region 을 그린다. **region 의 아래끝이 발바닥(높이 0)**,
  **가로 가운데가 몸 중심**이다. 원본 프레임의 아래끝을 바닥으로 잡으면 보스는 33px, 플레이어는 195px 어긋난 자리에 판정이 선다.
- 판정 id 는 **`팩/애니메이션/프레임`** 이고 애니메이션 이름은 **`.tres` 의 이름**이다 — 시트 파일 이름(`attack1.png`)이 아니라
  뷰가 부르는 이름(`attack`). 보스 `attack` · `attack2` · `attack3`, 플레이어 `attack` · `attack2`.
- 같은 입력이면 같은 출력이다 (정렬 · 반올림 규칙을 고정한다).

### 3.3 출력 — `overfit/data/hitboxes.json` (**커밋한다**)

```jsonc
{
  "_comment": "...",
  "_source": { "cell_px": 4, "white_min": 235, "alpha_min": 200, "fill_min": 0.25 },
  "medieval_king/attack/2": {
    "scale": 5.5, "region": [320, 2, 160, 103],   // .tres 의 region 그대로 — 어느 픽셀에서 뽑았나
    "rects": [ [x0, x1, y0, y1], ... ]            // 공격자 기준 · 월드 px · x 는 보는 쪽이 +
  },
  ...
}
```

**뽑을 목록은 이 파일의 키다.** 새 판정 모양이 필요하면 키를 하나 더하고 도구를 돌린다.

실측 (4px 칸 · 채움 25%):

| id | 사각형 | 가로 | 높이 |
|---|---|---|---|
| `medieval_king/attack/2` | 13 | −110 ~ +396 | 38.5 ~ 236.5 |
| `medieval_king/attack2/2` | 23 | −352 ~ +440 | 0 ~ 346.5 |
| `medieval_king/attack3/2` | 31 | −286 ~ +418 | 0 ~ 566.5 |
| `martial_hero/attack/4` | 18 | −40 ~ +230 | 2.5 ~ 172.5 |
| `martial_hero/attack2/4` | 16 | −40 ~ +240 | 12.5 ~ 132.5 |

- 좌표는 **공격자 기준**이다. x 는 몸 중심에서 보는 쪽이 +, y 는 발바닥에서 위로. 공격자가 뒤돌면 x 만 뒤집는다.
- 테스트가 이 파일에 대해 지킨다: 비어 있는 모양이 없다 · 사각형이 뒤집혀 있지 않다 · 기록된 배율이 `balance.json` 과 같다.
- **PNG 는 커밋하지 않는다.** `git ls-files overfit | grep -c '\.png$'` 는 0 을 유지한다.

### 3.4 몸통 (맞는 쪽)

| | 가로 | 세로 |
|---|---|---|
| 플레이어 | 중심 ± 30 | 발 ~ 발 + 120 |
| 보스 | 중심 ± 85 | 발 ~ 발 + 297 |

몸통은 **사각형 그대로 둔다.** 보스 `attack3` f2 처럼 몸이 낮게 숙인 장면도 있지만, 몸통까지 그림을 따라가게 하는 것은 이번 범위가 아니다.

보스 키 297 은 `idle` 첫 장을 **region 안에서** 잰 값이다 — 불투명 세로 49..102 · 5.5배 = 297.0, 같은 장의 폭 170.5 가
`half_width` 85 와 맞는다. `bosses.json` 에 `height` 로 둔다.

### 3.5 판정 규칙

한 번 휘두르는 것(= 판정 한 장)은:

1. **궤적 프레임이 떠 있는 동안 내내 살아 있다.** 지금은 판정 프레임에 들어서는 한 틱에만 물었는데,
   그러면 흰 궤적이 눈앞에 보이는데 두 틱 뒤에 걸어 들어간 사람이 안 맞는다.
2. 매 틱 상대 몸통이 사각형 중 하나라도 겹치는지 본다. 겹치면:
   - 대시 무적 중이면 → 이 틱은 넘어간다 (**창이 끝나기 전에 무적이 풀리면 그 뒤 틱에 맞는다** — 다크소울과 같다)
   - 패리 창 안이면 → **패리** · 이 휘두름 끝
   - 가드 중이면 → **가드** 또는 **가드 붕괴** · 이 휘두름 끝
   - 아니면 → **맞음** · 이 휘두름 끝
3. **한 번 휘두르면 한 번만 맞는다.**
4. 창이 닫힐 때까지 한 번도 안 맞았으면 관측 **하나**를 남긴다 — 어느 틱에 무적이 먹었으면 `Dodged`,
   아니면 마지막 틱에서 계산한 빗나간 이유 (§7).

**틱 반올림은 한 곳에서 정한다.** 8fps 한 장은 0.125초 = 7.5틱이다. 창은 초로 적고 `t_start ≤ t < t_start + dur`
로 비교한다 — 60Hz 에서 0.85초 시작이면 51~58틱, 8틱이다.

## 4. 보스

### 4.1 패턴 A — 3연격

| 시각 (초) | 그림 | |
|---|---|---|
| 0.000 ~ 0.725 | `attack1` f0 | **칼을 든 자세 = 예고** (0.725초) |
| 0.725 ~ 0.850 | f1 | |
| **0.850 ~ 0.975** | **f2** | **★ 1타 · 피해 8** |
| 0.975 ~ 1.300 | f3 | 다음 공격까지 붙잡고 선다 |
| 1.300 ~ 1.550 | `attack2` f0 → f1 | |
| **1.550 ~ 1.675** | **f2** | **★ 2타 · 피해 8** |
| 1.675 ~ 2.400 | f3 | |
| 2.400 ~ 2.650 | `attack3` f0 → f1 | |
| **2.650 ~ 2.775** | **f2** | **★ 3타 · 피해 14** |
| 2.775 ~ 3.250 | f3 | 끝 |

- 판정 시각 0.85 / 1.55 / 2.65 와 피해 8 / 8 / 14 는 **v0.6.0 1단계 그대로**다.
- **링이 없으므로 예고는 그림이다.** 1타 앞의 0.725초 동안 칼을 든 채 멈춰 있는 것이 지금 예고 링이 하던 일을 한다.
  2·3타는 연격의 박자가 예고다.
- 판정 모양: `medieval_king/attack1/2` · `attack2/2` · `attack3/2`.
- **어느 타든 패리하면 연격이 그 자리에서 끊긴다** (§4.3).

### 4.2 패턴 B — 점프 공격

| 시각 (초) | 그림 | |
|---|---|---|
| 0.00 ~ 0.40 | `jump` f0 | 웅크린 자세 = 예고 |
| 0.40 | 도약 | **이 순간 플레이어의 위치를 향해.** 그 뒤로는 안 따라간다 |
| 0.40 ~ 0.75 | `jump` f1 | 상승 |
| 0.75 ~ 1.00 | `attack3` f0 → f1 | 공중에서 휘두르기 시작 |
| **1.00 ~ 1.125** | **`attack3` f2** | **★ 착지 · 바닥 전체 · 높이 0 ~ 60 · 피해 12** |
| 1.125 ~ 1.50 | f3 | 끝 |

- 공중 궤적은 **포물선을 식으로** 그린다 — `y(s) = 4H·s(1−s)`, `s ∈ [0,1]`, `H = 280px`.
  물리 적분이 아니라 식인 이유는 착지 시각이 **정확히** 1.00초여야 하기 때문이다.
- 착지 자리는 **도약 순간 플레이어 위치에서 보스 쪽으로 몸 둘 폭(85 + 30)만큼 앞**이다. 아레나 안(85 ~ 1835)으로 자른다.
- 착지 판정은 **바닥 전체** `[0, 1920] × [0, 60]` 이다 — 그림에서 뽑지 않는다. 유저가 "지면 전체" 라고 했다.
- **패리 불가.** 가드 · 점프 · 대시로 피한다.
  점프로 넘으려면 착지 순간 발이 60 위에 있어야 하는데, 점프 체공 1.02초 중 **0.91초**가 그 조건을 만족한다.
- 보스는 공중에서도 몸통이 따라 올라간다. 플레이어 칼(높이 ~172)이 닿는지는 그 자리의 기하가 정한다.

### 4.3 패리 성공

- **연격이 그 자리에서 끊긴다.** 남은 타격은 안 온다.
- 보스는 `hit` 모션(**`hit_white` 아님**)을 재생하고 **푸른 톤으로 1.5초** 굳는다.
- 화면이 살짝 흔들리고 히트스톱이 걸린다 — 길이는 지금의 `feel.hitstop_frames`(7프레임)를 그대로 쓴다.
- 경직이 끝나면 패턴 간격(0.8초) 뒤 다음 패턴을 굴린다.

**1.5초의 근거** — 반격 2연격이 확실히 들어가는 길이다.

```
패리 성공 ─┬─ 반응          ~0.20
           ├─ 1타 닿음       0.28   (반응 + 선딜 0.083)
           └─ 2타 닿음       1.12   (+ 1타 0.25 + 2타 선딜 0.667)
경직 끝       1.50           반응이 0.58초까지 늦어도 2타가 들어간다
```

반격 한 번에 10 + 30 = **40**, 보스 체력 200 이니 **다섯 번 받아치면 이긴다.**

### 4.4 패턴 굴리기

1단계 명부는 둘이다. 패턴이 끝나면 간격 0.8초 뒤 `Det` 으로 둘 중 하나를 굴린다 — 지금과 같은 방식이다.
**지금은 무작위가 맞다.** 회피 기록을 읽어 고르는 망이 이 자리에 들어오고, 그때 무작위가 대조군이 된다.

## 5. 플레이어

### 5.1 2연격 — `J`

| | 그림 | 한 장 | 선딜 | 판정 | 후딜 | 합 | 피해 |
|---|---|---|---|---|---|---|---|
| 1타 | `attack1` f3 → **f4** → f5 | 12fps | 0.083 | 0.083 | 0.083 | **0.25** | 10 |
| 2타 | `attack2` f0~f3 → **f4** → f5 | **6fps** | 0.667 | 0.167 | 0.167 | **1.00** | **30** |

- 1타는 **v0.6.0 즉발 그대로**다 (f3 부터 시작해 칼 빼는 장을 건너뛴다).
- **1타 도중 `J` 를 다시 누르면** 1타가 끝나는 틱에 2타가 이어진다. 안 누르면 서 있는 자세로 돌아간다.
- 2타는 **반속(6fps)** 이다. 칼을 세우는 f0~f3 이 0.67초라 "크게 한 방" 이 보인다.
- 판정 모양: `martial_hero/attack1/4` · `attack2/4`.
- **끝까지 커밋.** 공격 중에는 가드 · 패리 · 대시 · 이동이 안 된다.
- 스태미나는 타마다 14 (v0.6.0 `attack_cost` 그대로).

### 5.2 가드 — `↓` (또는 `S`)

- **누르고 있는 동안** 가드다. **못 움직인다.**
- 피해의 25% 만 받고 스태미나를 피해의 1.8배 문다. 모자라면 **가드 붕괴** — 1.1초 굳고 전액을 맞는다.
- **땅에서만.** 공중에서 누르면 무시한다.
- 가드 중에 공격 · 패리 · 대시로 **바로** 넘어갈 수 있다.
- 스태미나는 `Idle` 일 때만 찬다 — 가드 중에는 안 찬다 (v0.6.0 그대로).

### 5.3 패리 — `K`

- 누르면 `attack2` **f0~f3** (칼을 사선으로 세운 자세)을 **12fps 로 0.333초** 재생한다. 그동안 커밋.
- **누른 순간부터 0.133초** 안에 맞으면 패리. 그 밖이면 **그냥 맞는다** — 가드가 아니다.
- 스태미나 15 (v0.6.0 `parry_cost` 그대로).
- **연타 징벌은 걷는다.** 창 0.133 / 커밋 0.333 이라 누를 때마다 60% 는 무방비로 서 있다 —
  연타는 이미 스스로 벌을 받는다. `parry_memory_window` · `parry_spam_window` 를 지운다.

### 6.1 디버그 — 판정 보기

> 유저: "히트박스들 볼수있는 디버깅 커맨드도 만들어두세요"
> 유저: "고도에 히트박스와 판정 그런 기능들이 다 있을텐데요? 따로 보여주는 옵션도 있을겁니다"

**보여주기는 Godot 의 기능을 쓴다 — Visible Collision Shapes.** 따로 그리는 오버레이는 만들지 않는다.

| | |
|---|---|
| 켜기 | 에디터 **Debug → Visible Collision Shapes**, 또는 `HITBOXES=1 tools/build.sh run` (엔진 인자 `--debug-collisions`) |
| 끄기 | 실행 중에는 못 켜고 끈다 — `SceneTree.debug_collisions_hint` 문서가 "실행 중에 바꾸도록 설계되지 않았다" 고 한다. 시작할 때 정한다 |
| 보이는 것 | 보스 판정(이 틱에 규칙이 대 본 것) · 선딜 중 **다음** 판정이 칠 자리 · 파이터 칼 · 두 몸통. 파이터 몸통 색이 무적 · 패리 창 · 가드일 때 바뀐다 |
| 스크린샷 | `HITBOXES=1 tools/build.sh shots` — 판정이 그려진 사진은 `out/shots/` 에만 남고 `docs/shots/` 로 안 넘어간다 |

**판정은 Godot 물리로 옮기지 않는다.** 학습 데이터는 봇이 **Godot 없이** 헤드리스로 수백만 판을 돌려 만든다.
판정이 `Area2D` 에 있으면 판마다 엔진을 띄워야 하고, "같은 시드면 같은 결과"(리플레이 골든)도 물리 스텝에 묶인다.
`CLAUDE.md` §1 의 "규칙은 Godot 을 모른다" 를 컴파일러가 막는 이유가 이것이다.

그래서 이렇게 잇는다: 규칙이 판정 사각형을 계산하고, 뷰(`HitboxDebug`)는 **매 프레임 그 사각형을
`CollisionShape2D` 로 옮겨 놓기만** 한다. 충돌 계산을 하나도 안 하는 노드(Area2D · monitoring 끔 · 레이어 0)라
Godot 의 디버그 표시가 그것을 그려 줄 뿐이다.

**규칙이 실제로 대 본 사각형을 그린다 — 뷰가 다시 계산하지 않는다.** 뷰가 `hitboxes.json` 을 따로 읽어 좌우를
뒤집고 발 위치를 더하면, 규칙 쪽 그 계산에 버그가 있어도 표시는 멀쩡해 보인다 — 가장 필요한 순간에 거짓말하는
도구가 된다. 규칙은 **이 틱에 댄 (모양, 놓은 자리)** 를 기록만 해 두고(할당 없음 · 봇은 안 읽는다),
표시가 물을 때 사각형으로 편다.

- 켜고 띄웠을 때만 노드를 세운다 — 안 켰으면 사각형을 옮기는 비용도 없다.
- 켜졌을 때 `[debug][D] hitboxes=on` 을 남긴다.
- 옛 판정(좌우 대칭 거리 띠)도 **사각형 두 장**(앞 · 뒤)으로 같은 통로를 탄다 — 그래서 1번 PR 에서부터 쓸 수 있다.

## 7. 계측

**10축 계약은 그대로다.** 모양이 바뀌는 것은 "왜 안 맞았나" 뿐이다.

### 7.1 빗나간 이유

판정이 모양이 되면서 다시 가른다. 창이 닫히는 마지막 틱에서, 상대 몸통을 **판정 모양 전체의 외곽 상자**와 견준다.

| 결과 | 조건 | 기록되는 수단 |
|---|---|---|
| `MissedTooFar` | 몸이 외곽 상자의 **가로 범위 밖** | 간격 (그 거리를 만든 것이 대시면 대시 — #46 규칙 그대로) |
| `MissedByHeight` | 가로로는 안인데 **외곽 상자 위** | 점프 |
| **`MissedByGap`** (신규) | 외곽 상자 **안인데 빈 칸** — 초승달 안쪽 같은 곳 | 간격 |

`MissedTooClose`(#46 의 안쪽 주머니)는 **`MissedByGap` 으로 흡수된다.** "보스 발밑이 비어 있다" 는 이제
"모양에 빈 곳이 있다" 의 한 경우다.

### 7.2 지우는 것 · 남는 것

| | |
|---|---|
| 지운다 | `DodgeEvent.ChargeTier` · `PlayerAxes.ChargedGreedSamples` — 차지가 없다 |
| 남긴다 | `GreedWindow` — "보스가 휘두르는 순간 공격 중이었나" 는 2연격에도 그대로 뜻이 있다 |
| 살아난다 | `jump_reliance` · `jump_timing_bias` — `attack1` 과 착지 판정을 점프로 넘을 수 있다 |
| 죽은 채 | `airborne_at_impact` 의 예측력 — 대공 판정이 없다. 정의는 남긴다 |

## 11. 위험

| | |

| **8fps 한 장 = 7.5틱** | 창의 반올림을 한 곳에서 정하지 않으면 뷰와 규칙이 반 틱씩 어긋난다 (§3.5) |
