## 1. Q 표 보스

### 1.1 칸 (상태)

결정의 관측(`BossObservation` 의 벡터)에서 다섯을 잘라 키 하나로 잇는다. 관측에서 자르는 것은 망과 **같은 입력**에서 출발했다는 것을 지키려서다.

| 칸 | 값 |
|---|---|
| 결정 지점 | 자유로워짐 · 쉬기 · 다가가기 · 물러서기 · 닿음 · 캔슬 (6) |
| 파이터와의 거리 | `|dx| / 아레나 폭` 이 0.1 · 0.2 · 0.35 아래 · 그 위 (4) |
| 파이터가 떠 있나 | 높이가 15px 넘나 (2) |
| 파이터의 행동 | `FighterAction` (늦은 관측 그대로) |
| 보스의 지금 동작 | 없음 · 명부의 칸 (캔슬 지점만 값이 있다) |
| 형태 | 1 · 2 · 3 |

모두 곱하면 수천 칸이지만 실제로 닿는 칸은 훨씬 적다. **칸을 더 잘게 자르면 표가 못 채워지고, 굵게 자르면 판을 못 가른다** — 그것이 이 대조군이 보이려는
것이다(우산 §2 "아이템이 늘면 표가 무너진다").

### 1.2 고르기

- 표에 있는 칸이면 **열린 칸 중 Q 가 가장 큰 칸**(같으면 앞의 칸). 표에 없는 칸이면 열린 칸 중 무작위.
- 학습 중에는 ε 의 확률로 열린 칸 중 무작위(ε 은 0.3 에서 0.05 로 줄인다).
- 난수는 `Det.Roll01` · `Det.RollInt`(도메인 `BossControl` · 결정 번호 · k2 로 갈래) — 같은 시드면 같은 판이다.
- 열린 칸이 하나뿐인 결정(자유로워짐)은 표가 안 배운다(망과 같다).

### 1.3 배우기 — 몬테카를로 Q

- 판마다 결정 i 의 할인 보상 `G_i = r_i + γ^(span_i/12) · G_{i+1}` — 보상 · γ(0.99) · 결정 간격(12틱)은 PPO 와 같다(`train.json`).
- `Q[s,a] += α (G − Q[s,a])` · α 0.1. 판들은 표를 얼린 채 병렬로 돌고, 바퀴 끝에 판 번호 순으로 고친다 — 스레드 수와 무관하게 같은 표다.
- **같은 판 수**: 셀프 플레이의 보스가 본 판 수와 같은 51,200 판(200 바퀴 × 256 판).
- **상대는 시험 묶음 그 자체**(봇 함대 + 파이터 r05 · r10 · r15 · r20). 시험을 보고 배운 것이라 Q 표에 유리하다 — 그래도 지면 망이 이긴 것이 분명하다.
- 모두 C# 이다(`tools/factory` 의 `--qtrain`) — 칸을 자르는 함수가 한 언어에만 있어야 고르기와 배우기가 같은 칸을 본다.

## 2. 비교 관문

`tools/build.sh gate --name=sp-1` — 같은 시험 묶음 · 같은 시드(`compare_seed`) · **보스마다 512 판**.

| 보스 | 무엇 |
|---|---|
| 무작위 | 열린 칸에서 같은 확률 — 바닥 |
| 규칙 | 0.11 의 보스 — 무작위 계획 + 폭탄 끊기 |
| Q 표 | §1 |
| 1 · 2 · 3페이즈 | `overfit/data/boss_net/form1~3.json` 을 판 내내 |
| 게임의 보스 | 셋을 형태마다 바꾸는 `FormNetController` — 사람이 만나는 보스 |

열마다: 보스 승률 · 파이터에게 준 피해(평균) · 보스가 잃은 체력(평균) · 판의 길이(초).

**통과: 3페이즈의 승률 ≥ max(규칙, Q 표) + 10%p.** 512 판의 승률의 표준오차는 많아야 2.2%p 이고 둘의 차이는 3.1%p 다 — 10%p 는 그 세 배다.

결과는 `ml/rl/gate/sp-1.json` 에 싣고 커밋한다 — 행 · 통과 여부 · 입력(망 · 표 · 상대)의 sha256. 관문은 몇 분 걸려 커밋 게이트에 안 넣는다.
떨어지면 README 에 그대로 적고 릴리즈를 멈춘다(유저에게 묻는다).
