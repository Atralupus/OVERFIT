## 0. 무엇을 만드나

보스의 판을 강화학습이 먹을 **경험**으로 바꾸는 길이다.

```
학습기(Python · 조각 5)                      판을 도는 일꾼(.NET · 이 조각)
  가중치 JSON  ───────────────────────────▶  tools/build.sh rollout --weights=…
                                              판 수백 개를 병렬로 · 결정마다 관측 → 정책망 → 칸 뽑기
  steps.bin · episodes.csv · manifest  ◀───  보상을 붙여 결정의 줄로 쓴다
```

- **관측**(`BossObservation`) — 결정의 판을 숫자 배열로. 칸 표가 계약이다(§2).
- **정책망**(`PolicyNet`) — 가중치 JSON 을 읽어 관측 → 칸마다 점수(로짓) · 판의 가치 하나. C# 사칙연산 · ReLU.
- **망 조종기**(`NetController`) — 결정마다 정책망을 돌려 가려진 칸을 빼고 뽑는다. 뽑은 칸 · 확률 · 가치를 적는다.
- **일꾼**(공장 콘솔의 `--rollout`) — 판을 병렬로 돌리고 보상을 붙여 쓴다. 상대는 봇 함대(조각 6 에서 파이터 망이 더해진다).
- **읽기**(`ml/rl/rollout.py`) — 학습기가 쓸 넘파이 배열로.

## 1. 우산 §5.1 을 고친다 — 판을 도는 쪽이 망도 돈다

우산은 "환경 서버가 결정마다 관측을 보내고 학습기가 행동을 돌려준다" 였다. 이 조각은 **일꾼(C#)이 정책망을 직접 돌린다** — 학습기는 가중치를 넘기고 경험을
받아 가중치를 고칠 뿐이다.

- **판 안에서 기다릴 곳이 없다.** 판은 결정을 `Tick` 안에서 동기로 묻는다(`IBossController.Decide`). 바깥에 묻고 기다리려면 판마다 스레드를 세우거나 판을
  뒤집어야 한다. 일꾼 안에서 망을 돌리면 지금 구조 그대로다.
- **결정마다 프로세스를 건너지 않는다** — 학습의 병목이 판 · 망 계산이 되고 주고받기가 아니게 된다.
- **같은 순전파를 게임이 쓴다** — 조각 7 의 게임 안 망이 이 `PolicyNet` 이다. 학습 때 본 망과 게임의 망이 같은 코드다.
- 대가: 학습기(넘파이)도 같은 순전파를 갖는다(PPO 의 확률 비율). 둘은 같은 수식이고 비트 일치는 조각 7 의 골든이 본다.

## 2. 관측 — 칸 표

모두 `double`. 자리는 아레나 폭(1920)으로, 높이는 300 으로, 체력은 최대로 나눈다. 칸 수 D 는 명부 길이 N 과 파이터 행동 수에 따라 정해지고 `BossObservation.Size`
가 낸다.

| 칸 | 수 | 무엇 |
|---|---|---|
| 결정 지점 | 6 | 원핫 — 자유로워짐 · 쉬기 · 다가가기 · 물러서기 · 닿음 · 캔슬 |
| 보스 | 10 | x/W · y/300 · 보는 쪽 · 체력/최대 · 형태 원핫(3) · 경직 게이지/최대 · 탈진 · 전환 중 |
| 보스의 움직임 | 4 | 원핫 — 없음 · 다가가기 · 물러서기 · 점프 |
| 보스의 동작 | N + 3 | 원핫(동작 없음 + 명부 N) · 동작의 진행(러너 틱/동작 길이) · 다음 캔슬 지점까지(틱/60 · 없으면 0) |
| 파이터(18틱 앞) | 8 + F | (파이터 x − 보스 x)/W · y/300 · 보는 쪽 · 보스 쪽을 보나 · 체력/최대 · 스태미나/최대 · 남은 폭탄/10 · 던지기 진행(0 ~ 1) · 행동 원핫(F) |
| 파이터의 최근 행동 | K × F | 18틱 앞에서 6틱씩 더 앞의 K = 8 모습의 행동 원핫 |
| 나는 폭탄 | M × 3 | M = 4 칸 — 있나 · 난 몫 · 놓은 자리의 (x − 보스 x)/W. 비면 0 |

- **아이템 칸은 공통 속성만**이다(우산 §4.1) — 폭탄이라는 이름이 없다. 아이템이 늘면 속성 칸을 넓히고 다시 학습한다.
- 파이터 칸은 늦은 관측의 고리(`SightBuffer`)에서 나온다 — 고리의 길이를 `18 + 6 × K` 로 늘린다.
- 관측은 **원하는 조종기에게만** 짓는다(`IBossController.WantsObservation`) — 규칙 · 무작위 조종기의 판은 할당이 안 는다.

## 3. 정책망

```jsonc
// 가중치 JSON
{ "obs": D, "actions": A, "roster": [...], "policy": [layer…], "value": [layer…] }   // layer = { "w": [[out × in]], "b": [out] }
```

- 은닉은 ReLU, 마지막 층은 선형. 정책은 A 개 로짓, 가치는 하나.
- `obs` · `actions` · `roster` 가 판과 다르면 읽을 때 거절한다 — 칸 표 · 칸 배치가 바뀌면 다시 학습한다.
- 가중치가 없으면(첫 바퀴) 일꾼은 **모든 열린 칸에 같은 확률**로 뽑는다(무작위 정책 · 가치 0).

## 4. 망 조종기와 뽑기

- 열린 칸의 로짓으로 소프트맥스 · `Det.Roll01(seed, Domain.BossControl, k1: 결정 번호)` 로 뽑는다(같은 시드 같은 판). 이 뽑기는 **학습용**이다 — 게임의 뽑기
  (exp 없는 결정 경로)는 조각 7 이 정한다.
- 열린 칸이 하나뿐인 결정(자유로워짐)은 **적지 않는다** — 고를 것이 없다. 그 사이의 보상은 앞 결정에 붙는다.
- 폭탄 반응은 안 켠다(`ReactsToBombs = false`) — 끊을지는 망이 고른다.

## 5. 보상

결정 i 의 보상은 결정 i 부터 다음에 적는 결정(또는 판의 끝)까지 생긴 일이다.

```
r = w_dealt × (파이터가 잃은 체력 / 파이터 최대) − w_taken × (보스가 잃은 체력 / 보스 최대) − w_time × (지난 틱 / 60)
    + 판의 끝: 이기면 w_win · 지면 −w_win (시간 초과도 짐)
```

가중치는 `ml/rl/train.json` 의 `reward` 다(조각 5 가 같은 파일에 PPO 수치를 더한다). 시작값: w_dealt 1 · w_taken 1 · w_time 0.002 · w_win 1.

## 6. 일꾼

`tools/build.sh rollout --weights=<json|none> --episodes=N --seed=S [--threads] [--out] [--train=ml/rl/train.json]`

- 판 e 의 시드와 상대(봇 함대의 성향)는 (S, e) 에서 나온다. 스레드 수와 무관하게 같은 출력이다(공장과 같은 `FactoryBatch` · 판 순서로 쓴다).
- 상대는 봇 함대(`FleetBot` · `fleet.json`). 판은 보스전 하나 · 체력 1200 · 세 페이즈 — 세 페이즈 모두 같은 망이다(페이즈마다 가중치는 조각 7).
- 출력(`out/rollout/<S>-<N>/`):
  - `steps.bin` — 결정 하나가 한 줄: `obs float32[D] · mask uint8[A] · action int16 · logp float32 · value float32 · reward float32 · done uint8 · episode int32`
  - `episodes.csv` — 판마다: 판 · 봇 · 결과 · 틱 · 보스가 잃은 체력 · 파이터가 잃은 체력 · 결정 수 · 보상 합
  - `manifest.json` — D · A · 명부 · 줄 수 · 두 파일의 sha256 · 초 · 초당 결정 · 가중치의 sha256 · 데이터 지문 · 커밋
- `[E]` 가 하나라도 나면 실패다(공장과 같은 판정).

## 7. 테스트

- 관측: 칸 수 · 칸의 자리(표대로) · 정규화 · 18틱 앞 · 최근 K 모습 · 나는 폭탄.
- 정책망: 손으로 셈한 작은 망의 로짓 · 가치 · 칸 수가 틀린 JSON 거절.
- 망 조종기: 가려진 칸을 안 뽑는다 · 같은 시드 같은 칸 · 확률이 로짓의 소프트맥스 · 가중치 없으면 고른 확률.
- 일꾼: 보상의 합이 판의 체력 변화와 맞는다 · 스레드 1 과 4 의 출력 바이트가 같다 · `[E]` 없이 끝까지.
- 파이썬: 일꾼의 출력을 읽어 모양과 마스크가 맞는다(`ml/rl/test_rollout.py`).
- 처리량을 재서 PR 에 적는다(무작위 정책 · 은닉 128 × 2 정책).

## 8. 하지 않는 것

- PPO · 학습(조각 5) · 파이터 망(조각 6) · 게임 안 망과 exp 없는 뽑기(조각 7).
