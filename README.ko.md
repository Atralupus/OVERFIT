# OVERFIT

[English](README.md)

OVERFIT 은 보스 하나를 두 단계에 걸쳐 싸우는 2D 횡스크롤 소울라이크다. 1단계는 플레이어가 공격을 피하는 방식을 기록한다.
2단계에서는 신경망이 기록을 읽고, 보스가 신경망의 예측으로 공격 패턴을 고른다.

목적은 플레이어의 회피 습관에 맞춰 패턴을 바꾸는 보스가 공정하고 재미있는지 확인하는 것이다.

## 2단계 패턴

2단계의 새 패턴은 1단계의 습관을 하나씩 노린다.

| <img src="docs/gifs/rush.gif" width="420"> | <img src="docs/gifs/grab.gif" width="420"> |
|---|---|
| **1타 → 돌진 → 3타** (`1타 돌진`)<br>멀리 서서 보스의 후딜에만 공격하는 플레이어를 노린다. | **1타 → 잡기** (`1타 잡기`)<br>대시로만 피하는 플레이어를 노린다. |
| <img src="docs/gifs/offbeat.gif" width="420"> | <img src="docs/gifs/jump3.gif" width="420"> |
| **엇박 3연격** (`엇박 3연격`)<br>패리를 자주 하는 플레이어를 노린다. | **점프 공격 ×3** (`점프 3연속`)<br>가드로 버티는 플레이어를 노린다. |

2단계의 다섯째 패턴은 1단계의 `3연격` 이다. GIF 는 고정된 대본과 한 가지 습관대로 움직이는 파이터로 찍었다(`tools/build.sh gifs`).
표의 짝은 설계 의도다. 망이 배운 짝은 [결과](#결과)에 있다.

## 신경망

```
봇 함대 ─▶ 데이터 공장 ─▶ 학습(NumPy) ─▶ network.json ─▶ 2단계 패턴 고르기(C#)
```

신경망(망)은 2단계 패턴 다섯 개 각각에 대해 플레이어가 맞을 확률을 예측한다. 패턴은 망이 고르지 않는다.
정해진 규칙이 예측 다섯 개로 보스의 패턴 목록을 만든다. 망이 이상한 값을 내도 게임은 깨지지 않는다.

### 입력

이번 런의 회피 관측(1단계와 2단계 재시도)에서 계산한 수 19개:

| 칸 | 뜻 |
|---|---|
| `dash_timing_bias`, `dash_timing_var` | 대시 타이밍 오차의 평균과 분산(이른지 늦은지) |
| `dash_direction_bias` | 대시 방향 — 보스 쪽인지 바깥쪽인지 |
| `jump_timing_bias` | 점프 타이밍 오차의 평균 |
| `jump_reliance`, `parry_reliance` | 다른 수단으로도 피할 수 있던 공격에서 점프나 패리를 고른 비율 |
| `airborne_at_impact` | 보스의 공격이 판정될 때 공중에 있던 비율 |
| `parry_rate` | 패리 성공률 |
| `greed` | 보스의 공격이 판정될 때 공격 중이던 비율 |
| `distance_bias` | 보스와의 평균 거리(px) |
| `guard_rate` | 보스의 공격을 가드로 받은 비율 |
| 개수 8개 | 위 값들의 근거가 된 관측 수: 전체 · 대시 · 점프 · 패리 · 가드 · 가드 붕괴 · 점프 가능 · 패리 가능 |

관측 3건으로 낸 값과 300건으로 낸 값을 망이 구분하도록 개수를 같이 넣는다. 입력은 `PlayerFeatures.From` 이 계산하고,
데이터 공장과 게임이 같은 함수를 쓴다.

패턴은 입력이 아니다. 패턴마다 출력이 따로 있다. 패턴 태그(패리 가능 여부 · 대시 창 · 사거리 등)는 쓰지 않는다.
`3연격` 과 `엇박 3연격` 은 태그가 같고 타이밍만 다르다.

### 학습 데이터

시도 한 번에 회피 관측이 20건 안팎이라 사람의 플레이로는 학습할 수 없다. 이 게임의 계측값을 입력으로 쓰는 기존 모델도 없다.
학습 데이터는 봇으로 만든다.

- **봇 함대.** 봇 10만 대. 절반은 한 가지 수단(대시 · 점프 · 패리 · 가드 · 거리 두기)에 기대고, 나머지 절반은 방어 수단 넷을 섞어 쓴다.
  봇마다 반응 속도 · 타이밍 흔들림 · 욕심 · 선호 거리 · 연속 공격 습관이 다르다. 봇은 플레이어와 같은 입력을 보내고,
  화면 없이 실제 전투 규칙으로 싸운다.
- **데이터 공장**(`tools/build.sh factory`, .NET 콘솔). 봇마다 1단계를 이길 때까지(최대 5번), 이어서 2단계를 최대 5번 친다.
  2단계 패턴은 무작위로 뽑는다. 2단계에서 패턴이 한 번 나올 때마다 표본 하나가 된다: 시도를 시작할 때의 입력 19개 · 패턴 ·
  라벨(맞았는지). 표본 1,383,287개, 4코어에서 약 105초.
- 난수는 순서대로 뽑지 않고 시드 · 스트림 · 키로 조회한다(`overfit/core/Det.cs`). 시드와 커밋이 같으면 스레드 수와 무관하게
  같은 바이트의 데이터가 나온다.

### 모델과 학습

- MLP 19 → 32 → 32 → 5, ReLU, 모수 약 1,900개. NumPy 로 역전파를 직접 썼고, 유한 차분으로 기울기를 검사한다.
- 손실은 뽑힌 패턴의 출력에만 거는 이진 교차 엔트로피다. 출력 편향은 패턴마다 기저율의 로짓에서 시작한다.
- 봇 번호로 나눈다: 학습 80% · 검증 10% · 시험 10%. 입력은 학습 몫의 평균과 편차로 표준화한다. Adam · 배치 1024 · 조기 종료.
- `tools/build.sh train` 이 `overfit/data/network.json`(가중치 · 표준화 · 기저율 · 학습 출처)과 `ml/report.md` 를 쓴다.

시험 몫(학습에 쓰지 않은 봇 1만 대):

| 패턴 | 로그 손실 | 기저율의 로그 손실 | ECE | AUC |
|---|---|---|---|---|
| 3연격 | 0.6131 | 0.6466 | 0.0085 | 0.653 |
| 점프 3연속 | 0.4595 | 0.4944 | 0.0052 | 0.687 |
| 1타 돌진 | 0.6060 | 0.6473 | 0.0123 | 0.669 |
| 1타 잡기 | 0.3639 | 0.3939 | 0.0090 | 0.695 |
| 엇박 3연격 | 0.6033 | 0.6296 | 0.0066 | 0.638 |

### 게임과의 연결

- **불러오기.** 게임은 부팅할 때 `network.json` 을 읽는다. `PlayerNet` 이 C# 에서 순전파를 한다. 사칙연산과 비교만, 정해진 순서로 쓴다.
  고정 입력 20개에서 파이썬과 C# 의 로짓이 비트까지 같고, `tools/build.sh check` 가 커밋마다 확인한다.
  학습 뒤에 게임 데이터가 바뀌면 부팅 로그에 `[net][W] stale` 이 남는다.
- **고르는 규칙**(`NetworkPicker`). 2단계의 시도를 시작할 때 한 번 정한다.
  1. 이번 런의 기록으로 입력 19개를 계산한다. 관측이 20건 미만이면 다섯 패턴을 모두 쓴다.
  2. 패턴마다 로짓을 얻는다. 들어 올림 = 로짓 − 기저율의 로짓. 평균적인 봇보다 이 플레이어가 얼마나 더 잘 맞는지를 나타낸다.
  3. 겨냥: 들어 올림이 0.405(오즈 1.5배) 이상인 패턴을 큰 순서로 최대 2개. 없으면 다섯 패턴을 모두 쓴다.
  4. 숨통: 겨냥이 아닌 패턴 중 로짓이 가장 낮은 패턴 하나.
  5. 보스는 시도가 끝날 때까지 겨냥 패턴과 숨통 패턴에서만 뽑는다.

  맞을 확률이 아니라 들어 올림을 쓰는 이유는 누구에게나 어려운 패턴만 고르지 않기 위해서다. 수치는 `overfit/data/balance.json` 의
  `picker` 에 있다. 다섯 패턴을 모두 쓰는 시도는 무작위 고르기와 뽑기 결과가 같다.
- **대조군.** 2단계 시도마다 시도 시드로 동전을 던진다. 50% 는 망이, 50% 는 무작위가 고른다. 로그에는 `arm=network` 또는
  `arm=uniform` 으로 남는다. 1단계는 습관을 재는 단계라 항상 무작위다.
- **시도 기록.** 끝난 시도마다 `user://attempts/<세션 시드>.jsonl` 에 JSON 한 줄을 남긴다: 갈래 · 뽑힌 패턴 · 회피 관측 · 입력 19개 ·
  패턴마다 맞았는지 · 망의 결정. 어디로도 보내지 않는다.
  - 봇으로 시도를 되살린다: `EXTRA="--history=<파일> --attempt=N" tools/build.sh demo`
  - 사람의 기록을 봇 함대와 비교한다: 파일을 `ml/human/` 에 옮기고 `ml/.venv/bin/python ml/sim2real.py` 를 돌린다.

### 결과

학습에 쓰지 않은 봇 5만 대(2단계 도달 31,580대)가 2단계를 같은 시드로 두 번 쳤다. 한 번은 망 보스, 한 번은 무작위 보스다
(`tools/build.sh evaluate` → `tools/build.sh validate`). 대괄호는 봇을 다시 뽑는 부트스트랩의 95% 구간이다.

| 항목 | 기준 | 결과 | |
|---|---|---|---|
| 가드 봇에게 잡기 | 무작위 보스보다 1.5배 이상 뽑히고, 맞는 비율이 오른다 | 2.36배, +3.7%p [+3.4, +4.1] | 통과 |
| 패리 봇에게 점프 3연속 | 같음 | 1.93배, +2.9%p [+2.5, +3.2] | 통과 |
| 점프 봇에게 돌진 | 같음 | 1.59배, +1.2%p [+0.8, +1.6] | 통과 |
| 대시 봇에게 잡기 | 같음 | 1.38배, +1.5%p [+1.2, +1.8] | 미달 |
| 숨통 | 좁힌 시도마다 있고, 겨냥 패턴보다 덜 맞는다 | 항상 있음, 59% 대 89% | 통과 |
| 약한 플레이어만 노리지 않는다 | 습관이 없고 반응이 느린 봇의 망 시도 중 80% 이상이 다섯 패턴을 모두 쓴다 | 38% [36, 41] | 미달 |
| 승률이 크게 떨어지지 않는다 | 망 보스 상대 2단계 승률이 무작위 보스 상대의 절반 이상 | 52% 대 56% | 통과 |
| 보정 | 패턴마다 ECE ≤ 0.05 | 0.004 ~ 0.022 | 통과 |

- 망이 배운 짝: 대시 → 잡기, 가드 → 잡기, 패리 → 점프 3연속, 점프 → 돌진. 패리 봇에게 엇박 3연격이 뽑힌 비율은 7.9%(무작위 20%),
  가드 봇에게 점프 3연속이 뽑힌 비율은 1.8% 다.
- 대시 봇: 망이 잡기와 점프 3연속을 함께 겨냥할 때가 많아, 잡기가 세 패턴 중 하나가 된다.
- 약한 봇: 습관이 없는 봇도 패턴마다 들어 올림이 0.65 정도 벌어져 0.405 를 넘는 패턴이 자주 생긴다.
- 망은 사람이 아니라 봇에게서 배웠다. 사람의 기록이 모이면 `ml/sim2real.py` 가 차이를 잰다.

전체 보고서: [`ml/validation.md`](ml/validation.md). 규칙을 바꿨을 때의 추정은
[설계 문서 §7.1](docs/superpowers/specs/2026-09-28-패턴-고르는-망-design.md#71-같은-봇에게-망-보스와-무작위-보스)에 있다.

## 플레이

macOS 빌드는 [Releases](https://github.com/Atralupus/OVERFIT/releases/latest) 에 있다. 서명하지 않은 빌드다.
macOS 가 막으면 시스템 설정 → 개인정보 보호 및 보안에서 "그래도 열기"를 누른다.

| 행동 | 키 |
|---|---|
| 이동 | ← → (A D) |
| 점프 | Space |
| 대시 | Shift |
| 공격 | J (다시 누르면 2연격) |
| 가드 | ↓ (S), 누르고 있는 동안 |
| 패리 | K |

소스에서 빌드하려면 Godot 4.7(mono)과 .NET 8 이 필요하다. [CONTRIBUTING.md](CONTRIBUTING.md) 를 본다.
